# 에이전트 시스템 (커리어캐쳐 업무용)

지금 실제로 맡기고 있는 일(블로그·카드뉴스/릴스·AI 리포트·보고서·PPT·리뷰·링크드인)을
하나의 흐름으로 묶는 운영 설계. 기존 `CLAUDE.md` 말머리 표와 `.claude/agents/`를 그대로 쓰고,
빠져 있던 "접수 → 체인 → 게이트 → 기록"만 더한다. 100개 스킬 라우팅 표는 참고용이며 전부 만들지 않는다.

> **위치**: 구조(조직도·업무 단위·품질 기준)의 정본은 `ai-assistant/`(`README.md`, `업무단위.md`, `checklist-품질.md`, `org.json`)다.
> 이 문서는 그 위에서 매일 돌리는 **운영 층**만 다룬다: 슬랙 접수 루틴, 업무별 체인 순서, 게이트, 작업 보드.
> 내용이 겹치면 `ai-assistant/`를 따른다. 에이전트·스킬을 추가하면 `ai-assistant/org.json`도 고친다.

## 1. 한눈에 보는 흐름

```
입구        슬랙 #blog-bot / 세션 요청 / 루틴(매시간 확인)
  ↓
접수        말머리로 업무 판단 → 작업 보드(state/BOARD.md)에 한 줄 등록
  ↓
정보 확인   빠진 정보는 최대 3개 질문 (지어내지 않는다)
  ↓
체인 실행   업무별 체인(3절)을 순서대로. 큰 주제는 /office
  ↓
게이트      ① 사실·개인정보 검수  ② 사용자 승인  ③ 상태 변경 승인
  ↓
전달·기록   커밋·푸시 → PR·머지 → 슬랙 스레드에 링크 → 보드 상태 갱신
```

## 2. 역할

| 역할 | 누가 | 맡는 일 |
|---|---|---|
| 접수·확인 | 루틴 "블로그 슬랙 자동 확인" | 새 메시지 감지, `state/slack_last_ts` 갱신, 변경 없으면 아무것도 보내지 않음 |
| 대장(팀장) | 메인 Claude (`ai-assistant/대장-업무규칙.md`) | 말머리 판단, 체인 순서 결정, 사용자 승인 요청, 보드 갱신 |
| 팀장 5명 | `lead-content` `lead-report` `lead-edu` `lead-coaching` `lead-workdesk` | 팀 작업 지시서 작성, 팀 결과 점검 (실행·승인은 하지 않음) |
| 조사 | `office-researcher` | 사실·출처 수집, 교차확인 |
| 기획 | `office-planner` | 목표·구조·목차 |
| 작성 | `office-blogger` / `office-writer` / `office-coverletter-writer` | 블로그·일반 문서·자소서 |
| 디자인 | `office-cardnews-designer` | 카드뉴스·릴스 문구와 디자인 가이드 |
| 강의 | `office-lecture-designer` | 강의안·커리큘럼·PPT 구조 |
| 검수 | `office-reviewer` | 사실, 지어낸 내용, 개인정보, 브랜드 문구, 분량 점검 (게이트 ①) |
| 제작 | general-purpose (Playwright·ffmpeg) | 이미지·카드·영상 파일 제작 |

새 에이전트는 당장 만들지 않는다. 같은 일이 3번 이상 반복될 때 그 일만 에이전트로 승격한다.

## 3. 업무별 체인

| 말머리 | 체인 (순서 고정) | 끝에 남는 것 |
|---|---|---|
| `[블로그]` | 같은 주제 검색(`posts/`, `output/`) → 정보 확인 → `blog-post` → `office-reviewer` → 사용자 승인 → `post.html` Artifact | `posts/날짜-slug/`, 슬랙 링크 |
| `[블로그]` 확장 | 위 결과 → 카드뉴스(`office-cardnews-designer`) → 인스타 캡션 → 검수 | `cardnews/`, 캡션 md |
| `[AI리포트]` | `ai-youtube-report` → 교차확인(`office-researcher`) → 주간은 `office-reviewer` | 포스터 PNG, 슬랙 `#ai-youtube-report` |
| `[보고서]` | 분량에 맞는 보고서 스킬(한 장/두 장/hwpx) → 검수 | docx 또는 hwpx |
| `[PPT]` | `office-lecture-designer`(+`edu-project-os`) → `pptx` → 검수 | pptx |
| `[코칭]` | 자소서 → `office-coverletter-writer`, 면접 → `interview-material-builder` → 검수 | 자소서 첨삭본, 면접 질문·경험노트 파일 |
| `[업무정리]` | `extract-work-items` → `verify-evidence` → 사람 승인 → `weekly-status-report` (규칙은 `workdesk/RULES.md`) | 승인된 업무 원장, 주간 보고 (원문·원장은 커밋하지 않음) |
| `[리뷰]` | `coupang-review` (메모 기반, 경험 지어내기 금지) | `reviews/` 원고, 등록은 직접 |
| 큰 주제 | `/office` (리서치 → 기획 → 작성 → 검수, 수정 최대 2회) | `office/날짜_주제/` |

모든 체인에 `careercatcher-skill-os`(브랜드·문체)가 함께 적용된다.

## 4. 게이트 (멈춰서 확인받는 지점)

1. **사실·개인정보 검수**: 참여자 수·성과·합격 사례 등 확인 안 된 사실 금지, 아이 실명·학교·얼굴 사진 금지, 외부 이미지 저작권 경고, 출처 없는 수치 금지.
2. **사용자 승인**: 원고를 보여 준 뒤 `AskUserQuestion`으로 진행 여부 확인. 사용자가 범위를 좁히면("블로그만") 그 범위를 넘지 않는다.
3. **상태 변경 승인**: `published` 표시, 슬랙 게시, PR 머지처럼 밖으로 나가거나 되돌리기 어려운 일. 발행완료는 사용자가 "발행완료 링크"로 알려 줄 때만 바꾼다.

## 5. 기록: 작업 보드

`state/BOARD.md` 한 파일에 진행 중인 일을 모은다. 상태는 기존 `meta.md`와 같은 값을 쓴다
(asked → answered → drafted → published). 보드는 모든 일의 색인이고, 세부 상태의 정본은 각 폴더의 `meta.md`다.
세션이 새로 시작되거나 컨텍스트가 길어져도 보드만 읽으면 어디까지 했는지 알 수 있다.
주간 회고 때 보드를 보고 막힌 일을 정리한다.

## 6. 운영 원칙

- 같은 자료(경험노트 등)는 업무가 달라도 원본 파일을 공유한다. 새로 쓰기 전에 `posts/`, `output/`, `office/`에서 같은 주제를 먼저 찾는다.
- 사용자가 주지 않은 사실은 쓰지 않는다. 모자라면 스레드에 질문(최대 3개)하고 일반 가이드 버전으로 쓰되 meta에 그렇게 적는다.
- 제3자 이미지는 쓰기 전에 저작권 경고를 한 번 하고, 사용자가 정하면 따른다.
- 작업 후에는 커밋·푸시, PR 생성·머지, 슬랙 스레드 링크 순서로 마무리한다.
- 같은 일이 반복되면 체인에 넣고, 체인에서 3번 이상 같은 수정이 나오면 스킬이나 검수 체크리스트로 올린다.

## 7. 확장 순서 (필요할 때만)

1. 보드 운영 시작 (이 문서와 함께 만들어 둠)
2. 반복이 많은 체인부터 `.claude/skills/`로 승격: 블로그 → 카드뉴스 확장(채널 변환), 강의 의뢰(인터뷰 → 제안서 → 발표자료)
3. 링크드인·스레드용 변환 스킬 (보류 중인 커리어허브 글에서 시작)
4. 주간 회고 루틴: 매주 보드를 읽고 막힌 일과 다음 주 우선순위를 슬랙에 한 번 정리
5. 100개 스킬 라우팅 표는 `docs/`에 참고로 두고, 실제로 쓰는 것만 말머리 표에 추가
