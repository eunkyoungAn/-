# 고객 데이터 → 신규 서비스 기획

## 1. 고객 불편 찾기
- 선택형 문항: 상위 항목과 비율(분모 포함), 집단별(운영형태·연령 등) 비교
- 문의 기록: 유형별 건수, 평균 처리 시간, 시간대별 차이 (접수 시각 기준. 기본은 업무 외 시간 = 20시 이후, 다르게 나누면 기준을 적는다)
- 자유 의견: 주제별로 묶고 대표 문장 2개씩 그대로 인용
- 비율의 분모가 30명(건) 미만이면 "해석 주의"

## 2. 문제 정의
- 후보 문제 3개를 표로 비교
  - 영향받는 사람 수: 설문 응답자 중 관련 항목을 하나라도 고른 인원 / 전체 응답자
  - 불편 강도: 처리 시간·만족도·지연 비율 중 데이터에 있는 것. 어떤 수치를 썼는지 적는다
  - 우리 조직이 해결 가능한지: 데이터에 정보가 없으면 [확인 필요]로 두고, 마지막에 사용자에게 확인 질문(인력·예산·담당 부서)을 한다
- 하나를 추천하고 "누가 / 언제 / 무엇 때문에 / 무엇을 못 하는가" 한 문장으로 정의

## 3. 기획서
| 항목 | 기준 |
|---|---|
| 서비스명 | 한 줄 이름 + 한 줄 설명 |
| 기획 배경 | 1단계 수치 2~3개 |
| 대상 고객 | 데이터 속 집단 기반 페르소나 1명 (합성 인물이므로 [가정] 표시) |
| 문제 정의 | 2단계 문장 + VOC 인용 |
| 핵심 기능 | 3개 이내 (MVP). 문제를 이루는 원인·장면 하나씩과 연결 |
| 운영 방식 | 사람이 하는 일 / AI가 하는 일 / 사람이 승인하는 지점 |
| 성과 지표 | 2~3개. 기준값은 데이터에서, 목표값은 [가정]. 기준값이 없는 지표는 "시범 시작 때 측정" |
| 시범 운영 | 대상·규모·기간·단계 [가정] |
| 위험과 대응 | 개인정보, 결과 품질, 담당자 업무 부담 |
| 필요 자원 | 인력·도구·예산 [가정] 또는 [확인 필요] |
- 한 장 보고서 양식으로 요청하면: 개요=서비스명+문제, 실행계획=시범 계획, 분석1~3=문제 근거, 해결방안=기능+운영, 결론=KPI·단기/중장기

## 4. 출력 형식
- 기본은 채팅 답변. 사실·분석·제안을 구분하고, 끝에 수치 대조표(문장 | 수치 | 근거 위치)를 붙인다.
- 한 장 보고서로 요청하면 위 칸 맞추기를 따른다.

## 5. 자기 검토
센터장 입장에서: 데이터로 뒷받침되지 않는 주장, 과소평가된 실행 부담, 더 작게 시험할 방법.

## 하지 않는 일
근거 없는 기대 효과·시장 규모, 가정을 사실처럼 쓰기, 개인정보를 AI 도구에 넣는 운영안.
