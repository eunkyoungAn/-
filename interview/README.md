# 커리어캐쳐 면접 리허설 (MVP)

강의 현장용 음성 면접 연습 도구입니다. 참여자는 휴대폰으로 질문을 듣고 말로 답한 뒤,
커리어캐쳐 기준 피드백을 받고 같은 질문에 다시 답해 전후를 비교합니다.
기획안: 「음성 면접 연습 시스템 기획안」(Claude Docs)

- 주소: `https://eunkyoungan.github.io/-/interview/` (main 브랜치에 합쳐진 뒤 열림)
- 빌드·설치 없이 GitHub Pages에서 바로 동작합니다.
- 구직자에게 나눠 줄 안내 문구, QR, 안내 이미지: `SHARE.md`

## 참여자 흐름

질문 고르기 → 질문 듣기(음성 읽기) → 준비 30초 → 60초 또는 90초 말로 답하기(실시간 글자 변환)
→ 받아 적은 글 확인·수정 → 피드백(다음에 고칠 한 가지, 잘한 점, 고칠 점, 바꿔 말하기 예시, 5개 항목 점수, 말하기 지표)
→ 한 가지 고쳐서 다시 답하기 → 전후 비교

## 내 질문 추가

질문 고르기 화면 맨 위에서 참여자가 연습하고 싶은 질문을 직접 넣을 수 있습니다(최대 20개, 150자).
추가한 질문은 그 휴대폰 브라우저에만 저장되고 서버로 보내지 않습니다.

## 이메일로 리포트 받기, 이용 방법, 키 안내

- 첫 화면에서 **피드백 리포트 받을 이메일**(선택)을 받습니다. 주소는 그 기기 브라우저에만 기억하고, "이메일로 리포트 받기"를 누를 때만 씁니다.
- 발송은 저장소 루트의 `mail-config.json`에 적힌 Google Apps Script 웹앱(`apps-script/Code.gs`, 기존 자소서 도구와 공용)을 씁니다. 설정 방법은 루트 `README.md`의 "메일 발송 설정". 하루 전체 80통, 같은 주소 5통 제한.
- `mailEndpoint`가 비어 있거나 발송에 실패하면, 리포트가 채워진 상태로 참여자 휴대폰의 메일 앱을 열고(길면 요약) 전체 리포트를 복사해 둡니다.
- 메일에는 리포트 글(질문, 답변, 피드백)만 들어갑니다. 영상은 보내지 않습니다.
- 첫 화면 **이용 방법 보기**: 순서, 준비, 세 가지 연습 방법, 내 자료로 질문 만들기, 피드백 읽는 법, 리포트 받기, 자주 묻는 질문.
- Gemini 키 카드: **키 받으러 가기**(https://aistudio.google.com/apikey) 버튼과 받는 방법 6단계, 주의사항.

## 평가 기준 (2026-11 대표 정리본 적용)

기준·가중치·주의점·근거 문헌은 `rubric.js` 한 파일에 있습니다. 바꾸려면 이 파일만 고칩니다.

| 항목 | 가중치 | 구분 | 매기는 방법 |
|---|---|---|---|
| 답변의 구체성 | 25% | 내용(주요 평가) | Gemini 연결 시 5·3·1점 행동기준으로 평가, 미연결 시 표현 규칙 |
| 직무역량 근거 | 25% | 내용 | 위와 같음 |
| 논리성과 질문 적합성 | 20% | 내용 | 위와 같음 |
| 음성 전달력 | 15% | 전달(코칭 지표) | 말 속도, 긴 침묵, 잦은 군말, 억양 변화. 목소리 높낮이·길이는 보지 않음 |
| 비언어적 전달력 | 10% | 전달 | 영상 녹화 시. 좌우 시선 이탈 비율, 반복 움직임. 위아래 시선은 감점 없음, 표정은 측정 안 함 |
| 영상 환경 | 5% | 전달 | 영상 녹화 시. 얼굴 보임, 밝기, 녹음 음량, 소음 |

- 총점 = 항목 점수(1~5) × 가중치를 100점으로 환산. 측정하지 않은 항목은 빼고 남은 가중치로 다시 나눕니다(화면에 표시).
- 하지 않는 판단(시선 이탈을 거짓말로, 낮은 목소리·방언·말더듬을 역량 부족으로, 움직임을 불안으로 해석 등)을 규칙과 AI 지시문에 넣었습니다.
- 피드백 화면과 리포트의 **평가 기준과 근거**에 항목별 기준, 주의점, 근거 등급(A·B·C), 참고 문헌이 표시됩니다.
- **피드백 리포트**: 종합 총점, 항목별 평균, 다음 연습 과제, 질문별 피드백, 평가 기준과 근거. 리포트 파일(HTML, 오프라인에서 열림), PDF(인쇄), 이미지, 글 복사로 내려받습니다.
- 시선 좌우·상하 구분, 움직임, 밝기 측정은 실제 얼굴로 검증 전입니다. 기준값(임계값)은 파일럿에서 조정합니다.

## 내 자료로 예상 질문 만들기 (참여자 본인 Gemini 키)

질문 고르기 화면의 **내 자료로 예상 질문 만들기**에서 진행합니다. 서버 없이 참여자 브라우저가 Gemini API를 바로 부릅니다(비용은 키 주인 부담).

1. Gemini 키 연결: Google AI Studio에서 만든 키. 기본은 이번만 쓰고, "이 휴대폰에 키 기억하기"를 고르면 브라우저에 저장. 모델 기본값 `gemini-3.1-flash-lite`, 없으면 `gemini-2.5-flash-lite`, `gemini-2.5-flash` 순으로 자동 대체
2. 지원 직무(필수)·회사, 자료(자기소개서, 경력기술서, 포트폴리오, 경험노트, 채용공고)를 **파일 첨부** 또는 붙여넣기. 보내기 전에 전화번호·이메일·주민번호 자동 가림
   - 한글(HWP·HWPX)·워드(DOC·DOCX)·글자 있는 PDF·TXT(UTF-8/EUC-KR): 휴대폰 브라우저 안에서 읽음, 파일 전송 없음(PDF는 `vendor/pdfjs/`의 pdf.js, HWP·DOC는 `files.js`의 자체 해석기)
   - 사진(JPG·PNG 등)·스캔한 PDF: 참여자 확인 후 본인 Gemini로 보내 글자 읽기(파일 그대로 전송, 가림 미적용 안내)
   - 암호 걸린 파일은 안내 문구, 한글 배포용 문서는 미리보기 글만 읽음. 화면의 "어떤 파일을 올릴 수 있나요?"에 형식별 설명
   - 질문 추출 코드 설명: `TECH.md`
   - 파일 이름으로 칸을 자동 배정(공고→채용공고, 경력→경력기술서 등, 모르면 자기소개서), 칸마다 따로 첨부도 가능, 칸당 15,000자
3. **예상 질문 바로 만들기**: 자료만 넣으면 핵심 역량 5개 추출부터 질문 생성까지 한 번에. "역량 먼저 확인하고 만들기"를 고르면 역량을 빼거나 추가한 뒤 생성
4. 역량별 본질문 + 공통 2개(자기소개, 지원동기). 질문마다 유형(경험형/상황형/직무형), 질문 의도, 꼭 보여 줄 근거, 평가 기준 2~3개, 자료 속 근거 문장, 예상 꼬리질문, 키워드, 핵심 답변 스크립트(자료에 없는 사실은 [ ] 빈칸)
5. "나의 예상 질문집"은 이 기기에만 저장, PDF·글 복사로 내보내기

키가 연결되어 있으면 모든 질문에서
- 본질문 답변 후 AI가 부족한 근거 하나를 골라 **꼬리질문**을 읽어 주고(건너뛰기 가능),
- 본질문+꼬리질문 답변을 **질문별 평가 기준**(충족/부분/미흡)과 두괄식·구조·구체성·직무 연결로 평가합니다. 전달·영상 분석은 기존 규칙 그대로.

**연결 점검(오류 원인 확인)**: 첫 화면 "AI 피드백·꼬리질문 (내 Gemini 키)" → **연결 점검**. 키 모양 → 키 확인(모델 목록) → 모델 → 글 생성 시험 → 형식 지정 응답 시험 순서로 시험하고, 실패한 단계의 원인·해결 방법·Google 원문 메시지와 마지막으로 난 오류를 보여 줍니다. "점검 결과 복사"로 강사에게 보낼 수 있고 키는 포함되지 않습니다. 오류 풀이 표는 `gemini.js`의 `explain()`.

설계 근거: 평가할 역량 정의 → 단순한 본질문 → 답변 맥락에 따른 꼬리질문 → 질문 의도와 맞춘 평가 기준(PRISM×몬스터 면접 질문 설계 글 참고).
무료 키는 입력 내용이 Google 서비스 개선에 쓰일 수 있어 화면에서 안내합니다.
실제 Gemini 키로는 아직 검증하지 않았습니다(모의 응답으로 흐름만 확인).

## 영상 모드 (선택)

첫 화면의 **답변 방식**에서 "영상 녹화"를 고르면 실제 화상 면접처럼 내 모습을 보며 답합니다.

| 항목 | 측정 방법 (모두 휴대폰 안에서) |
|---|---|
| 시선 | Google MediaPipe 얼굴 인식으로 0.2초마다 얼굴·눈동자 방향을 보고 카메라를 향한 시간 비율, 1초 넘는 이탈 횟수 |
| 억양 | 말하는 동안 목소리 높낮이 변화폭(반음). 목소리 높이 자체는 보지 않음 |
| 템포 | 분당 음절(음성 인식 글 기준), 2.5초 넘는 멈춤 횟수 |

- 녹화 영상은 피드백 화면에서 다시 보고 **이 영상 내 휴대폰에 저장**으로 저장합니다(아이폰: 공유 창의 "비디오 저장", 안드로이드·PC: 파일 내려받기).
- 영상과 분석 결과는 서버로 보내지 않습니다. 얼굴 인식 모델과 라이브러리도 이 사이트(`vendor/mediapipe/`)에서 불러옵니다.
- 시선 분석은 실제 얼굴로 아직 검증하지 않았습니다. 파일럿에서 아이폰·갤럭시로 확인이 필요합니다.
- 일부 기기에서는 카메라 녹화 중 음성 인식이 동시에 안 될 수 있습니다. 그때는 답변을 글로 입력하면 내용 피드백을 받을 수 있고, 영상 분석은 그대로 나옵니다.

## 두 가지 피드백 방식

| 방식 | 언제 | 내용 |
|---|---|---|
| 간이 피드백 | AI 서버 주소를 넣지 않았을 때(기본) | 이 기기 안에서 낱말 규칙으로 계산. 아무것도 전송하지 않음. 내용 판단은 거침 |
| AI 피드백 | 강사용 설정에 서버 주소·수업 코드를 넣었을 때 | Claude가 루브릭으로 평가. 질문·답변 글만 전송, 저장 안 함 |

전달 점수(길이·말 속도·군말)는 두 방식 모두 화면에서 같은 규칙으로 계산합니다. 글로 답하면 전달은 평가하지 않습니다.

## 강사가 수업에서 쓰는 법

1. 첫 화면 아래 **강사용 설정**에 AI 서버 주소와 수업 코드를 넣고 **배포 링크 복사**를 누릅니다.
2. 특정 질문만 쓰려면 링크 끝에 `&q=1,4,7`처럼 질문 번호를 붙입니다(번호는 `questions.js`).
3. 답변 시간은 `&t=90`으로 정할 수 있습니다.
4. 링크를 QR로 만들어 화면에 띄웁니다. 카카오톡으로 보내면 인앱 브라우저에서 마이크가 막힐 수 있어, 첫 화면이 "다른 브라우저로 열기"를 안내합니다.

예: `https://eunkyoungan.github.io/-/interview/?relay=https://careercatcher-interview.<계정>.workers.dev&code=수업코드&q=1,4,7,14&t=60`

## 고칠 수 있는 곳

| 바꿀 것 | 파일 |
|---|---|
| 질문 목록·힌트 | `questions.js` |
| 간이 피드백 규칙, 전달 점수 기준, 군말 목록 | `scoring.js` |
| AI 평가 기준·피드백 말투 | `worker/src/rubric.js` (수정 후 서버 다시 배포) |
| AI 모델·응답 깊이(effort)·허용 사이트 | `worker/wrangler.toml` |

## AI 평가 서버 배포 (Cloudflare Workers, 1회)

Claude API 키를 브라우저에 두지 않기 위한 작은 중계 서버입니다. Node.js 20 이상이 필요합니다.

```sh
cd interview/worker
npm install
npx wrangler login                       # Cloudflare 계정 로그인
npx wrangler secret put ANTHROPIC_API_KEY  # Claude API 키 입력
npx wrangler secret put CLASS_CODE         # 수업 코드(아무 문자열) 입력
npm run deploy                             # 끝나면 https://careercatcher-interview.<계정>.workers.dev 주소가 나옴
```

- 허용 사이트(`ALLOWED_ORIGINS`)에 등록된 주소에서 온 요청만 받습니다. 다른 곳에 올리면 `wrangler.toml`에 추가하세요.
- 수업 코드가 다르면 거절합니다. 과정이 끝나면 `CLASS_CODE`를 바꿔 링크를 닫을 수 있습니다.
- 모델은 `claude-opus-5-5`, effort는 수업 중 대기 시간을 줄이려 `low`가 기본입니다.
- 안전 분류기가 거절하면 서버에서 대체 모델로 다시 시도하는 설정(fallbacks)을 켜 두었습니다.
- 서버 상태 확인: `https://<서버 주소>/health`

## 개인정보

- 녹음 파일은 만들지 않습니다. 말한 소리는 브라우저 음성 인식 기능이 글자로 바꿉니다. Chrome은 Google 음성 인식 서버, 아이폰 Safari는 Apple 음성 인식(기기 또는 Apple 서버)을 거칩니다. 이 앱 쪽 서버로는 소리가 오지 않습니다.
- 참여자는 피드백 화면의 **피드백 저장하기**에서 오늘 연습한 질문 전체를 이미지(PNG), PDF, 글(복사)로 직접 저장할 수 있습니다. 저장 파일도 기기 안에서 만들어집니다.
- 이름·로그인·저장 기능이 없습니다. 화면을 닫으면 답변이 사라집니다.
- AI 서버는 답변을 저장하거나 로그에 남기지 않습니다.
- 첫 화면에서 수집·전송 범위와 "점수는 합격 예측이 아님"을 확인받습니다.

## 알려진 한계와 다음 단계

- 음성 인식은 브라우저 내장 기능(기획안의 A안)입니다. Chrome(안드로이드·PC), Safari(아이폰)에서 동작하고, 기기마다 품질이 다릅니다. 지원하지 않으면 자동으로 글로 답하기로 바뀝니다.
- 기획안 권장안인 서버 음성 인식(B안)은 아직 붙이지 않았습니다. 파일럿에서 A안 품질이 부족하면 `worker`에 변환 기능을 추가합니다.
- 음성 인식이 "음, 어" 같은 군말을 빠뜨리는 경우가 있어 군말 수는 실제보다 적게 나올 수 있습니다.
- 파일럿 전 확인: 아이폰, 갤럭시, 카카오톡 인앱 브라우저에서 마이크·인식 시험.
- 확장 1(강사 대시보드, 구글 시트 저장), 확장 2(맞춤 질문, 꼬리질문, 진척 기록)는 파일럿 후 진행합니다.
