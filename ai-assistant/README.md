# AI비서 플랫폼 (커리어캐쳐)

> 나는 **오케스트레이터**, AI는 **비서팀**.
> 각 AI의 강점을 알고 → 일을 나눠 맡기고 → 결과를 합치고 검증한다.
> (출처: 커리어캐쳐 「claude활용 오피스 작성 실무」 1·2회차, 2026.6.)

## 1. 플랫폼 구조 (5단계)

| 단계 | 하는 일 | 이 저장소에서 쓰는 것 |
|---|---|---|
| ① 접수 | 요청을 받아 어떤 업무 단위인지 판단 | 세션 말머리 `[보고서]` `[블로그]` 등, `CLAUDE.md` 업무별 표 |
| ② 맥락 (Project = 작업용 방) | 항상 알고 있어야 할 배경·자료를 깔아 둠 | `CLAUDE.md`, `careercatcher-skill-os`, `project-instructions/`, `sources/` |
| ③ 실행 (Skill = 작업 매뉴얼) | 정해진 절차·양식으로 결과물 생성 | 업무별 스킬·에이전트 (→ `업무단위.md`) |
| ④ 검수 | 품질 6요소 점검 + 사람의 마무리 | `office-reviewer`, `checklist-품질.md` |
| ⑤ 납품 | 저장·공유 | 커밋 → PR → main 병합, 슬랙 링크 |

- **Project vs Skill 구분**
  - Project(맥락): "무엇을 알고 있는가" — 대화 시작마다 항상 적용 (예: 인수인계 파일, 거래처 정보)
  - Skill(절차): "어떻게 할 것인가" — 그 작업이 필요할 때만 불러옴 (예: 한 장 보고서 양식)
- 둘을 **함께** 써야 "자료를 이해하고 정해진 방식으로 실행"하는 비서가 된다.

## 2. 폴더 안내

| 파일 | 내용 |
|---|---|
| `org.html` | **AI비서 조직도** — 대표 → 비서실장 → 7개 팀과 에이전트·스킬 (원본 `org.json`) |
| `업무단위.md` | **업무 단위 카탈로그** — 업무별 입력·절차·스킬·산출물·검수 포인트 |
| `checklist-품질.md` | 품질 6요소 + 사람의 몫(마무리) 체크리스트 |
| `project-instructions/보고서작성.md` | Claude/ChatGPT Project 지침에 붙여 넣는 보고서 작성 지침 |
| `prompts/` | 업무별로 바로 복사해 쓰는 프롬프트 (자료조사, 1차 분석, 2차 보고서, 스킬 만들기) |
| `sources/` | 비서가 참고할 원자료 목록과 요약 (강의 교안 등) |

## 3. 운영 원칙

1. **자료에 없는 내용은 추측하지 않는다** → `[자료 필요]`, `[확인 필요]`로 표시.
2. **사실·분석·권고를 구분**해서 쓴다. 핵심 결론은 앞에.
3. **객관적 데이터에는 출처**를 단다 (최신 2~3년 자료 우선).
4. 같은 주제는 새로 쓰기 전에 `posts/`, `office/`, `output/`에서 먼저 찾는다.
5. 개인정보(실명·학교·얼굴)는 넣지 않는다.
6. 자주 쓰는 일은 **스킬로 만든다**. 스킬에서 가장 중요한 건 `description`(언제 불러올지).
7. 토큰 절약: 질문은 묶어서, 출력 길이 명시, 주제 바뀌면 새 대화, 단순 작업은 가벼운 모델.

## 4. 새 업무 단위를 추가하는 방법

1. `업무단위.md`에 같은 형식으로 한 칸 추가 (ID, 입력, 절차, 스킬, 산출물, 검수).
2. 반복될 업무면 `skill-creator`로 스킬 생성 → description에 "이럴 때 사용" 문구를 꼭 넣기.
3. `CLAUDE.md` 업무별 스킬 표에 말머리와 스킬을 추가.
4. 에이전트·스킬을 추가·삭제하면 `org.json`을 고치고 `python3 ai-assistant/tools/build_org.py`로 조직도를 다시 만든다. 빠진 것이 있으면 검사에서 알려 준다.
