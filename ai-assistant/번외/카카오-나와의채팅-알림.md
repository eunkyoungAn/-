# [번외] 카카오톡 '나와의 채팅' 알림

> **번외 자료.** 기본 업무정리 에이전트(누구나 강의에서 만들 수 있는 버전)에는 넣지 않는다.
> API 키·로그인·토큰 관리가 필요해 난이도가 높다. 심화 과정이나 개인 확장용으로 참고만 한다.
> 구현 예시 코드(`kakao_notify.py`, 테스트 11개)는 [PR #92](https://github.com/eunkyoungAn/-/pull/92) 시점 커밋 `1f04890`에 남아 있다. 실제 카카오 서버로는 보내 보지 않았다.
> **매일 업무 요약 알림**(Apps Script 방식, 2026-11-20)은 [`kakao-daily-summary/`](kakao-daily-summary/)에 코드와 설치 안내가 있다. 이것도 실제 전송은 대표가 연결한 뒤 처음 확인한다.

## 결론: 가능하다 (조건 있음)
카카오 공식 **'나에게 보내기' API**로 내 카카오톡 '나와의 채팅'에 알림을 보낼 수 있다.

| 항목 | 내용 (2026-11-20 공식 문서 원문 확인) |
|---|---|
| 보내는 곳 | `POST https://kapi.kakao.com/v2/api/talk/memo/default/send` |
| 필요한 것 | 카카오 디벨로퍼스 앱, 카카오 로그인 사용 설정, 리다이렉트 URI 등록, 동의항목 **카카오톡 메시지 전송(talk_message)**, 제품 링크 관리의 웹 도메인 등록 |
| 받는 사람 | 로그인한 **본인**의 나와의 채팅만 (다른 사람·단톡방 아님) |
| 메시지 | 텍스트 템플릿, 본문 최대 200자. `link`는 필수이고 앱에 등록한 웹 도메인이어야 함 |
| 발송 건수 | 나에게 발송은 심사 승인 전에도 제한 없음 |
| 액세스 토큰 | REST API 방식 6시간 |
| 리프레시 토큰 | 2달. 만료 1달 전부터 갱신 가능. 만료가 1개월 미만으로 남았을 때 갱신하면 새 토큰이 나오고 이전 것은 폐기 |
| 클라이언트 시크릿 | REST API 키에 기본으로 켜져 있음. 토큰 요청에 `client_secret`을 함께 보내야 함 |
| 할 수 없는 것 | 단톡방·개인 대화 **읽기**, 다른 사람에게 보내기(친구에게 보내기는 사용 권한 신청 필요) |

출처: 카카오디벨로퍼스 [카카오톡 메시지 REST API](https://developers.kakao.com/docs/latest/ko/kakaotalk-message/rest-api), [카카오톡 메시지 이해하기](https://developers.kakao.com/docs/latest/ko/kakaotalk-message/common), [기본 템플릿](https://developers.kakao.com/docs/latest/ko/message-template/default), [카카오 로그인 REST API](https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api), [카카오 로그인 이해하기](https://developers.kakao.com/docs/latest/ko/kakaologin/common). 문서별 근거 표는 [`kakao-daily-summary/README.md`](kakao-daily-summary/README.md).
아직 확인이 필요한 것: talk_message 동의항목을 비즈 앱 전환 없이 설정할 수 있는지. 문서에는 "[선택, 이용 중 동의]: 제한된 기능 제공, 사용 권한 신청"으로 적혀 있어, 콘솔에서 [설정]이 눌리는지 직접 봐야 한다.

## 연결 순서 (개요)
1. [카카오 디벨로퍼스](https://developers.kakao.com)에서 앱 만들기 → REST API 키 확인
2. 카카오 로그인 활성화, Redirect URI 등록
3. 동의항목에서 카카오톡 메시지 전송(talk_message) 설정
4. 브라우저로 로그인·동의 → 인가 코드 → 토큰 발급(`kauth.kakao.com/oauth/token`)
5. 액세스 토큰으로 나에게 보내기 호출, 만료되면 리프레시 토큰으로 갱신(새 리프레시 토큰으로 교체)

## 넣는다면 지킬 원칙 (업무 자동화 계획서 8장 B)
- 받는 곳은 본인 나와의 채팅만. 다른 사람·단톡방 발송, 대화 읽기는 하지 않는다.
- 알림에는 숫자만 넣는다(예: "진행 3건 · 지연 1건"). 이름·업무 제목·원문은 넣지 않는다.
- 초안 → 사람 승인 → 전송. 승인 뒤 내용이 바뀌면 다시 승인.
  - 매일 요약은 건수만 담는 문구 형식을 한 번 승인받아 그 형식으로 자동 전송한다. 담는 항목이나 문구를 바꾸면 다시 승인받는다.
- 키·토큰은 저장소 밖에 두고 화면·로그에 찍지 않는다.

## 결과가 불명확할 때
- 전송 응답을 받지 못했으면 **나와의 채팅을 먼저 확인**한다. 와 있으면 그대로 둔다.
- 안 왔을 때만 다시 보낸다. 응답이 없었다는 이유만으로 자동 재발송하지 않는다(중복 알림 방지).

## 강의에서 다룬다면
- 기본 과정: "이런 확장도 가능하다" 소개 1장 정도.
- 심화 과정: 개발 경험자 대상으로 별도 회차. 카카오 앱 설정·토큰 발급에만 30분 이상 걸린다.
