# [번외] 카카오톡 매일 업무 요약 알림

> **번외 자료.** 기본 에이전트와 조직도(`org.json`)에는 넣지 않는다. 대표 개인 확장용이다.
> 배경과 원칙은 [`../카카오-나와의채팅-알림.md`](../카카오-나와의채팅-알림.md).
> 작성 2026-11-20. **실제 카카오 서버로는 아직 보내 보지 않았다.** 아래 5단계에서 대표가 처음 확인한다.

## 한눈에

- 매일 오전 8시 30분 무렵(한국 시간), 작업 보드(`state/BOARD.md`)의 구역별 **건수만** 대표 본인 카카오톡 '나와의 채팅'으로 보낸다.
- 받는 사람은 카카오에 로그인해 동의한 본인 한 명이다. 다른 사람이나 단톡방으로는 가지 않는다.
- 보내는 문구 (2026-11-20 보드 기준 예시)

```
커리어캐쳐 업무 요약 11/21(토)
응답 대기 12건
발행 대기 4건
보완 필요 5건
```

말풍선 아래 [보드 열기] 단추를 누르면 GitHub의 작업 보드가 열린다.

## 움직이는 방식

```
대장(Claude)이 일을 받거나 끝낼 때 보드를 고쳐 main에 올림
        ↓
Google Apps Script가 매일 아침 보드를 읽어 건수를 셈   ← 이 폴더의 Code.gs
        ↓
카카오 '나에게 보내기' API → 대표의 나와의 채팅
```

Claude 세션이 카카오로 직접 보내지 않고 Apps Script를 거치는 이유는 두 가지다.

1. 클라우드 세션은 끝나면 사라진다. 6시간마다 바뀌는 카카오 토큰을 보관하고 갱신할 곳이 없다.
2. 키와 토큰을 저장소나 세션에 두지 않기 위해서다. 키와 토큰은 대표의 Apps Script 안에만 있다.

보드에서 `## 응답 대기`, `## 발행 대기`는 표의 줄 수를, `## 보완 필요`는 글머리표 줄 수를 센다. 구역 제목이 바뀌어 찾지 못하면 0건으로 적지 않고 "확인 필요"로 보낸다.

## 준비물

- 알림을 받을 카카오 계정, 구글 계정
- 처음 한 번 설정에 30분 안팎 (어림값)

## 설치 순서

리다이렉트 URI로 Apps Script 웹 앱 주소를 쓰기 때문에 **Apps Script를 먼저** 만든다.

### 1단계. Apps Script 만들고 웹 앱으로 배포

1. <https://script.google.com> → [새 프로젝트]. 이름 예: `카카오 매일 요약`
2. 편집기의 기본 코드를 지우고 [`Code.gs`](Code.gs) 전체를 붙여 넣은 뒤 저장한다.
3. [배포] > [새 배포] > 유형 [웹 앱]
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **나만**
4. 권한 승인 화면이 나오면 승인한다. (외부 서비스 연결, 트리거 관리 권한)
5. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사해 둔다.

### 2단계. 카카오 디벨로퍼스 앱 설정

1. <https://developers.kakao.com> 로그인 → 앱을 만든다. (앱 이름, 회사명, 카테고리 입력)
2. [카카오 로그인]에서 사용 설정 **상태를 ON**으로 바꾼다.
3. [앱] > [플랫폼 키] > [REST API 키]를 연다.
   - [카카오 로그인 리다이렉트 URI]에 1단계의 웹 앱 URL을 그대로 넣고 저장한다.
   - 같은 화면에서 **REST API 키** 값과 **클라이언트 시크릿** 코드를 확인한다.
4. [카카오 로그인] > [동의항목] > [접근권한] > [카카오톡 메시지 전송]에서 [설정]을 누른다.
   - 동의 단계는 [선택 동의]나 [이용 중 동의] 중 하나, 동의 목적 예: `업무 요약 알림을 본인에게 전송`
5. [앱] > [제품 링크 관리] > [웹 도메인]에 `https://github.com`을 등록한다. ([보드 열기] 단추가 여는 주소의 도메인)

### 3단계. 스크립트 속성에 값 넣기

Apps Script 왼쪽 톱니바퀴 [프로젝트 설정] > [스크립트 속성] > [스크립트 속성 추가]

| 속성 | 값 |
|---|---|
| `KAKAO_REST_API_KEY` | 2단계에서 확인한 REST API 키 |
| `KAKAO_CLIENT_SECRET` | 2단계에서 확인한 클라이언트 시크릿 코드 (기능을 껐다면 비워 둠) |
| `KAKAO_REDIRECT_URI` | 1단계의 웹 앱 URL (카카오에 등록한 것과 글자 하나까지 같아야 함) |

### 4단계. 카카오 계정 연결

1. 브라우저에서 웹 앱 URL을 연다. 표에 "스크립트 속성: 입력됨"이 보여야 한다.
2. [카카오 계정 연결하기] → 카카오 로그인 → [카카오톡 메시지 전송] 동의
3. "카카오 연결 완료" 화면이 나오면 끝이다.

### 5단계. 보내 보기

Apps Script 편집기 위쪽 함수 목록에서 골라 [실행]을 누른다.

1. `previewDailySummary`: 보내지 않고 문구만 실행 로그에 찍는다. 건수가 보드와 맞는지 본다.
2. `sendTestMessage`: 확인용 메시지 1건을 보낸다. 카카오톡 나와의 채팅에 왔는지 본다.
3. `sendDailySummary`: 오늘 요약을 실제로 보낸다. (같은 날 다시 실행하면 보내지 않는다)

### 6단계. 매일 알림 켜기

`installDailyTrigger`를 한 번 실행한다. 다음 날부터 매일 8시 30분 무렵에 온다(앞뒤 15분 안에서 실행).

## 쓰는 동안

| 하고 싶은 일 | 방법 |
|---|---|
| 시각 바꾸기 | `Code.gs` 맨 위 `SEND_HOUR`, `SEND_MINUTE`를 고쳐 저장하고 `installDailyTrigger`를 다시 실행 |
| 알림 끄기 | `removeDailyTrigger` 실행 |
| 연결 끊기 | `removeDailyTrigger`, `clearKakaoTokens` 실행 후 카카오계정의 연결된 서비스 관리에서 앱 연결 끊기 |
| 실패 확인 | Apps Script 왼쪽 [실행] 메뉴에서 실패한 실행과 사유 확인 |
| 연결 화면(`doGet`) 코드를 고쳤을 때 | [배포] > [배포 관리] > 수정 > 버전 [새 버전]. 새 배포를 만들면 URL이 바뀌어 리다이렉트 URI를 다시 등록해야 한다 |

**토큰은 손대지 않아도 된다.** 액세스 토큰은 6시간, 리프레시 토큰은 2달짜리다. 매일 실행될 때 액세스 토큰을 갱신하고, 리프레시 토큰 만료가 1개월 안으로 들어오면 카카오가 새 리프레시 토큰을 주므로 그때 바꿔 저장한다. 알림을 2달 넘게 꺼 두었다면 4단계부터 다시 연결한다.

### 자주 나는 오류

| 표시 | 원인 | 조치 |
|---|---|---|
| KOE004 | 카카오 로그인 사용 설정이 꺼짐 | 2단계 2번 |
| KOE006 | 등록하지 않은 리다이렉트 URI | 2단계 3번의 URI와 `KAKAO_REDIRECT_URI`가 같은지 확인 |
| KOE010 | 클라이언트 시크릿 누락 또는 오타 | `KAKAO_CLIENT_SECRET` 확인 |
| KOE303 | 인가 코드 요청과 토큰 요청의 리다이렉트 URI가 다름 | `KAKAO_REDIRECT_URI` 확인 |
| KOE320 | 인가 코드를 두 번 썼거나 만료됨 (연결 완료 화면을 새로 고침한 경우) | 웹 앱 URL을 다시 열어 처음부터 |
| KOE322 | 리프레시 토큰 만료 또는 없음 | 4단계부터 다시 연결 |
| HTTP 403, -402 | 카카오톡 메시지 전송 동의 없음 | 2단계 4번 확인 후 4단계 다시 |
| "응답을 받지 못했습니다" | 카카오 응답이 오지 않음 | 나와의 채팅을 먼저 확인. 와 있으면 그대로 두고, 안 왔을 때만 직접 다시 실행 |

구글 계정을 여러 개 로그인한 브라우저에서는 웹 앱 URL이 열리지 않을 수 있다. 그때는 시크릿 창에서 Apps Script를 만든 계정 하나로만 로그인해 연다. (일반적으로 알려진 현상, 이 프로젝트에서는 확인 전)

## 지키는 원칙

- 받는 곳은 본인 나와의 채팅뿐이다. 다른 사람·단톡방 발송, 대화 읽기는 하지 않는다.
- 알림에는 건수만 넣는다. 업무 이름·제목·원문은 넣지 않는다.
- 위 문구 형식을 대표가 한 번 승인하고 그 형식으로만 자동 전송한다. 담는 항목이나 문구를 바꾸면 다시 승인받는다.
- 키·토큰은 스크립트 속성에만 둔다. 코드, 저장소, 실행 로그, 연결 화면에 찍지 않는다.
- Apps Script 프로젝트를 다른 사람과 공유하지 않는다. 편집 권한이 있으면 스크립트 속성을 볼 수 있다.
- 응답을 받지 못했을 때 자동으로 다시 보내지 않는다(중복 알림 방지). 토큰이 거절(401)된 경우에만 한 번 갱신해 다시 보낸다.

| 확인 필요 | [카카오톡 메시지 전송] 동의항목을 비즈 앱 전환 없이 설정할 수 있는지. 문서에는 "[선택, 이용 중 동의]: 제한된 기능 제공, 사용 권한 신청"으로 적혀 있고, 나에게 발송은 "심사 승인 전: 발송 건수 제한 없음"이라 심사 전에도 된다고 읽히지만 콘솔에서 [설정]이 눌리는지는 2단계 4번에서 확인 |
| 확인 필요 | `https://github.com`을 웹 도메인으로 등록할 수 있는지 (소유 확인 절차가 있는지 문서에 없음). 안 되면 `Code.gs`의 `LINK_URL`을 등록 가능한 주소로 바꾼다 |
