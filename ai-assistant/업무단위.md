# AI비서 업무 단위 카탈로그

업무 하나 = **입력 → 절차 → 산출물 → 검수** 한 묶음.
모든 업무에 `careercatcher-skill-os`(브랜드·문체)를 함께 적용한다.
세션 이름: `[말머리] 자료명 | 산출물` (예: `[보고서] 여행선호조사 | 한장보고서`).

## R1. 자료 수집·사실 확인
- **입력**: 주제, 기간(기본 최근 2~3년), 원하는 자료 종류(통계·사례·논문)
- **절차**
  1. 주제를 질문 3~5개로 쪼갠다.
  2. 웹·학술 자료를 찾고, 수치는 출처 2곳 이상 교차 확인.
  3. 사실/해석을 나눠 메모. 출처 링크·발행일 기록.
- **스킬**: `office-researcher` (짧은 조사), `deep-research` (여러 출처 종합)
- **외부 도구(사람이 직접 쓸 때)**: Perplexity(실시간·출처), Liner(웹+논문), NotebookLM(내 자료 기반 정리·인포그래픽)
- **산출물**: `office/<작업폴더>/01_research.md`
- **검수**: 정확성·신뢰성·최신성 (→ `checklist-품질.md`)
- **프롬프트**: `prompts/01_자료조사.md`

## R2. 조사자료 분석 (1차)
- **입력**: 엑셀·설문 원자료 (예: 여행 선호지역 조사 120명)
- **절차**
  1. 자료 개요 확인: 조사 목적·대상·기간·응답자 수
  2. 전체 순위, 항목별 수·비율
  3. 집단별(연령·목적·유형) 차이를 전체 평균과 비교
  4. 주목할 결과 3~5개, 표본이 작은 집단은 해석 주의 표시
- **스킬**: `xlsx`, Project 지침 `project-instructions/보고서작성.md`
- **산출물**: 분석 결과 요약 md (표 포함)
- **검수**: 수치가 원자료와 일치하는지, `[자료 필요]` 표시 여부
- **프롬프트**: `prompts/02_1차분석.md`

## R3. 분석결과 보고서 (2차)
- **입력**: R2 결과, 보고서 분량·형식(한 장/두 장/자유)
- **절차**
  1. 구성: 핵심 요약 → 목적·개요 → 전체 분석 → 집단별 특징 → 시사점 → 권고 → 실행 과제 → 한계
  2. 핵심 결론을 맨 앞에, 수치와 근거를 연결
  3. 사실·분석·권고를 구분, 개조식 업무보고 문체
- **스킬**: 한 장 → `one-page-report-docx`/`-hwpx`, 두 장 → `two-page-report-docx`, 그 외 → `docs`
- **산출물**: `output/` 또는 `office/<작업폴더>/` 아래 docx·hwpx
- **검수**: 품질 6요소 + 사람의 마무리(제목 줄바꿈, 페이지 수·여백, 강조 볼드)
- **프롬프트**: `prompts/03_2차보고서.md`

## R4. 양식(hwpx) 채우기
- **입력**: hwpx 양식 파일 + 주제(또는 내용 메모)
- **절차**: 양식 구조 분석 → 칸별 분량 맞춰 작성 → hwpx로 다시 묶기 → 한글에서 열어 확인
- **스킬**: `hwpx-autofill-conversion`, 회기별 운영일지는 `operation-log-hwpx`
- **산출물**: 채워진 hwpx
- **검수**: 양식 칸 넘침, 페이지 수, 표 깨짐

## R5. 기업·기관 실사
- **입력**: 사업자등록번호 또는 기관명
- **절차**: 공공 데이터 교차 조회 → 사실만 나열(점수·등급 없음) → 최근 이슈는 별도 리서치
- **스킬**: `biz-health-check`, `office-researcher`
- **산출물**: 실사 리포트(HTML/md)
- **검수**: 조회일 표기, 출처 표기, 판단 문구 넣지 않기

## E1. 강의 설계·교안
- **입력**: 의뢰 기관, 대상, 회차·시간, 목표
- **절차**: 사전 인터뷰 → 성공 기준 확정 → 차시별 강의안 → 슬라이드 구조 → 실습자료·지침 파일 → 리허설 점검
- **스킬**: `office-lecture-designer` + `edu-project-os` → `pptx`
- **산출물**: 강의계획서, 차시 강의안, PPT, 실습 파일(지침·예제 데이터)
- **검수**: 실습 흐름이 무료 요금제에서도 되는지(안 되면 대체 도구 안내)

## E2. 강의자료 재활용
- **입력**: `sources/`에 등록한 교안·PDF
- **절차**: 교안 요약(`sources/`) → 용도 결정(블로그·카드뉴스·요약 PDF·후속 강의) → 해당 업무 단위로 넘김
- **산출물**: 해당 업무 산출물
- **검수**: 교안 속 타인 저작물(설문 그래프, 캡처) 출처 표기, 기관 로고 사용 여부

## C1~C4. 콘텐츠 (기존 흐름 유지)
- C1 블로그: `docs/FLOW.md`, `.claude/skills/blog-post/SKILL.md`
- C2 카드뉴스: `office/카드뉴스_디자인가이드.md`, `templates/카드뉴스_*`
- C3 쿠팡 리뷰: 메모 기반, 경험 지어내기 금지, 등록은 직접
- C4 AI 리포트: `docs/AI-REPORT-FLOW.md`

## J1~J2. 취업 코칭
- J1 자소서: 경험노트 + 채용공고 → `office-coverletter-writer` → 첨삭 근거 표시
- J2 면접: 이력서·자소서·기출 → `interview-material-builder` → 예상질문 25, 경험노트, STAR·PREP 표
- 공통: 참여자 실명·연락처는 결과물에 남기지 않는다.

## W1. 대화·회의 업무 정리 (업무정리 데스크)
- **입력**: 제공 권한이 있는 카카오톡 내보내기 TXT/CSV, 회의 메모
- **절차**: 원문 등록 → 업무 후보·근거·확인 질문 추출 → 자동 검증 → 원문 대조 검토 → **사람 승인** → 확정 업무 원장 → 상태 관리 → 주간 보고
- **스킬·에이전트**: `extract-work-items`(`work-extractor`), `verify-evidence`(`evidence-verifier`), `weekly-status-report`, 도구 `workdesk/tools/workdesk.py`
- **산출물**: 확정 업무 목록, 주간 진행 보고서
- **검수**: 모든 업무에 원문 근거, 담당자·기한 명시/추정/미정 구분, 승인 안 된 후보는 보고하지 않음
- **자세히**: `workdesk/README.md`

## S1. 스킬 만들기·관리
- **언제**: 같은 설명을 세 번 이상 반복했을 때
- **방법 3가지**: Claude와 함께 만들기(요구가 복잡할 때) / 지침 직접 작성 / 남이 만든 스킬 업로드
- **핵심**: `description`에 "무엇을 하는지 + 언제 쓰는지 + 호출 문구"를 적는다.
  - 예) `회의 내용을 입력하면 A4 한 장 보고서로 정리. "한 장 보고서 써줘" 요청 시 사용.`
- **주의**: 스킬이 많으면 고르는 데 토큰을 씀 → 자주 쓰는 1~2개 위주, 필요하면 스킬 이름을 직접 말하기.
- **프롬프트**: `prompts/04_스킬만들기.md`
