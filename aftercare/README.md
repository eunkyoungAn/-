# 내일동행 · 고용서비스 사후관리

구직자별 고용서비스와 사후관리 이력을 각 담당자의 PC·브라우저에 암호화해 보관하는 웹앱입니다.
GitHub Pages에서 정적 파일로 바로 실행되며, 빌드나 설치가 필요하지 않습니다.

## 사용 형태

- 각 담당자가 같은 주소를 이용하되, 자기 PC·브라우저 프로필에서 독립적으로 관리합니다.
- Google 로그인, 기관 공동 저장, 기기 간 자동 동기화는 없습니다.
- 주소나 브라우저 프로필이 바뀌면 별도 저장소로 취급됩니다. 자료를 옮기려면 이전 주소에서 암호화 백업을 받아 새 주소에서 복원합니다.

## 시작 순서

1. 12자 이상의 암호로 저장소를 만듭니다.
2. 사후관리자에서 담당자를 등록합니다. 담당자 명부이며 로그인 계정은 아닙니다.
3. 구직자에게 담당자와 관리 시작일·종료일을 지정합니다.
   - 명단이 엑셀(.xlsx)·CSV 파일로 있으면 구직자 관리 → **엑셀로 일괄 등록**으로 한 번에 올립니다. 열 이름을 보고 항목을 자동으로 맞추고, 미리보기에서 확인한 뒤 등록합니다. 파일은 브라우저 안에서만 읽으며 전송·보관되지 않습니다. 암호·보안(DRM)이 걸린 파일은 엑셀에서 암호 없이 다시 저장한 뒤 올립니다.
4. 진행한 고용서비스, 결과, 다음 연락일, 증빙을 등록합니다.
5. 출력·증빙에서 대상·기간·서비스를 골라 PDF 인쇄, CSV, PNG, 증빙 ZIP으로 저장합니다.
6. 보안·백업에서 암호화 백업을 받고 저장소를 잠급니다.

## 보관과 출력

- AES-256-GCM, PBKDF2-SHA256 600,000회. 암호·키는 서버로 보내지 않습니다.
- 기록과 첨부파일을 하나의 암호화 묶음으로 IndexedDB에 저장합니다.
- 파일 하나는 3MB, 기록당 10개, 저장소 전체 증빙 약 30MB 제한입니다.
- 같은 브라우저 저장소는 한 탭에서만 열리며 10분 미사용 시 잠깁니다.
- 화면을 열어둔 상태와 내려받은 출력물은 암호화 저장소 보호 범위 밖입니다.
- 백업 복원은 현재 자료 전체를 교체하며 백업 당시의 암호를 사용합니다.
- 암호를 잊었거나 백업 없이 브라우저 자료를 지우면 복구할 수 없습니다.
- 이름 가리기는 기본 인적사항에만 적용됩니다. 자유 입력 내용과 원본 증빙의 개인정보는 직접 확인하세요.
- 진행 요약 PNG는 입력 자료를 요약한 이미지이며 실제 진행을 증명하는 원본 자료가 아닙니다.
- CSV는 엑셀에서 열 수 있는 표 파일입니다. PDF는 브라우저 인쇄 창에서 'PDF로 저장'을 선택합니다.

## 저장소 운영 원칙

- 외부 라이브러리, 분석 추적, 폰트 요청 없이 실행됩니다. (CSP로 외부 연결 차단)
- 이 저장소는 공개 저장소이므로 **실제 구직자 자료나 암호화 백업 파일을 절대 올리지 마세요.**
- 파일 구성: `index.html`, `app.js`, `model.js`, `vault.js`, `export.js`, `import.js`, `style.css`, `theme.css`, `app-id.txt`
