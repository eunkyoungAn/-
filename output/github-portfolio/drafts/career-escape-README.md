# Career Escape — AI 경험정리·자기소개서·면접 준비 웹앱

> 구직자가 휴대폰으로 희망직무와 경험을 입력하면, AI가 경험카드·자기소개서 초안·면접질문 10개를 만들어 이메일로 보내 주는 진로·취업 교육용 웹앱

🔗 **Demo**: [배포 주소 — 확인 필요] · 커리어캐쳐(CareerCatcher) 교육용 MVP

## 1. Problem
- 취업 교육 현장에서 구직자는 "경험이 없다"고 말하지만, 실제로는 경험을 **직무 언어로 꺼내는 방법**을 모르는 경우가 많습니다.
- 강사 한 명이 수업 시간 안에 모든 교육생의 경험을 1:1로 질문·정리하기 어렵습니다.
- 지원 기업 정보를 찾아도 공식 사실과 추측이 섞여 자기소개서에 잘못 들어가곤 합니다.

## 2. Solution
| 단계 | 사용자가 하는 일 | 결과물 |
|---|---|---|
| 1. 목표 정하기 | 희망직무(필수), 희망기업·채용공고(선택) 입력 | 직무 분석 |
| 2. 경험 찾아보기 | AI 질문에 하나씩 답변(최대 5개) | 경험 답변 |
| 3. 경험 정리하기 | — | 경험카드 1개, 자기소개서 초안 1개, 면접질문 10개 |
| 4. 커리어 완성 | 결과 확인 | 화면 표시 + 이메일 발송 |

희망기업이 공시 대상이면 OpenDART의 직원 현황·재무 정보를 "희망기업 한눈에" 카드로 보여 주고 지원동기·면접질문에 반영합니다.

## 3. Technology
- **실행 환경**: Google Apps Script 웹앱 + Google Sheets(DB)
- **AI**: Gemini API — 질문 생성, 자기소개서·면접질문 작성
- **공공데이터**: OpenDART API (`empSttus`, `fnlttSinglAcnt`)
- **API 키 정책**: Gemini는 참가자 본인 키(브라우저에만 저장, 서버·시트·로그 미저장, 오류 메시지 마스킹), DART는 운영자 키(Script Properties)

## 4. Process
1. 수업에서 반복되는 질문("무슨 경험을 써야 하나요?")을 단계형 흐름으로 정리
2. 한 번에 하나씩 묻는 인터뷰 방식으로 질문 설계
3. 운영 비용 0원을 목표로 참가자 키(BYOK) 구조 채택
4. 기업분석에서 사실과 AI 해석을 분리하도록 개선
5. `TEST_CASES.md` 시나리오로 점검 후 수업 적용 — [적용 횟수·인원: 확인 필요]

## 5. Validation
- **사실/해석 분리**: DART 수치는 "공식 사실", 직무 연관 부문 해석은 "AI 추정(사실 아님)"으로 화면에 명시
- **환각 방지**: AI는 DART 직원현황에 실제 있는 부문명만 사용, "합계" 등 소계 행은 제외
- **기업명 매칭**: `(주)`, `㈜`, `주식회사`, 공백을 무시하고 상장사 우선
- **테스트**: `TEST_CASES.md` 시나리오
- **개인정보**: 이름·이메일 수집 → 운영 전 처리 안내·보유기간 고지 필요. API 키는 저장하지 않음

## 6. Limitations & Improvements
- 비상장·소규모 기업은 공시가 없어 채용공고 중심으로만 분석
- 채용공고 URL 본문은 자동 수집하지 않음(붙여넣기 권장)
- 메일은 웹앱 소유자 계정에서 발송되어 Google 일일 한도 적용
- 링크를 아는 누구나 접속 가능 → 수업용 접근 제한 검토
- 개선 계획: [예: 강사용 결과 대시보드, 자기소개서 첨삭 기준표 연동]
