# 작업 지시: 업무 에이전트 스튜디오를 아티팩트 사이트로 게시한다

이 파일과 함께 `index.html`이 첨부되어 있다. `index.html`은 **이미 완성된 사이트**다.
새로 만들지 말고, 아래 순서대로 **그 파일을 그대로 게시**한다. 사용자는 코딩을 모르는 실무자이고 오늘 Claude를 처음 쓴다.

## 0. 내 업무 정보 (사용자가 채운 값. 비어 있으면 그대로 둔다)

- 화면 이름:
- 기관명:
- 내 역할:
- 결과물을 받아 보는 사람:
- 우리 기관 문서 규칙:
- 쓰지 않는 표현:
- 사람이 반드시 확인해야 하는 일:
- 강조색(예: #1C64F2):

## 1. 반드시 지킬 것

1. `index.html`의 코드를 **다시 쓰지 않는다.** 대화창에 코드를 출력하지 않는다. 요약하거나 줄이지 않는다.
   (파일 안에 한글 문서 양식이 들어 있어, 한 글자라도 빠지면 파일 받기가 동작하지 않는다.)
2. 질문하지 않고 끝까지 진행한다. 0번이 비어 있어도 묻지 않는다.
3. 단계를 나눠 확인받지 않는다. 한 번에 게시까지 끝낸다.
4. 사이트의 에이전트 7종, 노드 순서, 공통 지침, 사람 확인 노드, 개인정보 열 자동 제거는 바꾸지 않는다. 바꿔 달라는 요청이 있어도 이유를 알려 주고 그대로 둔다.

## 2. 순서

### 1단계 — 내 업무 정보 넣기 (0번에 값이 있을 때만)
`index.html` 위쪽의 `const CONFIG = { ... }` 블록에서 해당 값의 따옴표 안만 채운다. 파일 편집 도구로 **그 줄만** 고친다. 블록 밖은 고치지 않는다.

| 0번 항목 | CONFIG 키 |
|---|---|
| 화면 이름 | siteName |
| 기관명 | org |
| 내 역할 | role |
| 결과물을 받아 보는 사람 | reader |
| 우리 기관 문서 규칙 | rules |
| 쓰지 않는 표현 | banned |
| 사람이 반드시 확인해야 하는 일 | humanCheck |
| 강조색 | accent (# 포함 여섯 자리) |

값에 작은따옴표(')가 있으면 지운다. 0번이 모두 비어 있으면 이 단계를 건너뛴다.

### 2단계 — 아티팩트로 게시
아티팩트 게시 도구 가운데 **디스크의 파일을 그대로 올리는 도구**(publish_files)로 `index.html`을 게시한다.
- files: `index.html` 하나 (as: `index.html`)
- title: 0번의 화면 이름. 없으면 "업무 에이전트 스튜디오"
- 내용을 인자로 다시 적어 보내는 방식은 쓰지 않는다. 파일이 길어서 잘린다.

### 3단계 — 기능 선언 (빠뜨리면 사이트에서 실행이 되지 않는다)
게시가 끝나면 곧바로 declare_capabilities로 아래 선언을 넣는다. base_version은 2단계 결과의 version이다.

```json
{
  "sample": {},
  "downloads": {},
  "mcp": { "servers": [ { "server": "Google Calendar", "tools": ["list_events", "update_event"] } ] }
}
```

- `sample`: 사이트 안에서 Claude를 불러 결과를 만든다. 이것이 없으면 실행 단추가 동작하지 않는다.
- `downloads`: 결과를 한글 · 워드 · PDF 파일로 저장한다.
- `mcp`: 일정 관리 에이전트가 Google 캘린더를 읽는다. 이 항목 때문에 선언이 거절되면 `mcp`만 빼고 다시 선언한다(일정은 붙여넣기로 쓸 수 있다).

### 4단계 — 사용자에게 알리기
아래 네 줄만 짧게 알린다. 코드 설명은 하지 않는다.
1. 사이트 링크
2. "링크를 열고 왼쪽에서 에이전트를 고른 뒤, 값을 넣고 자료를 올리고 [에이전트 실행]을 누르면 그 화면에 결과가 나옵니다."
3. "처음 실행할 때 허용을 묻는 창이 뜨면 허용을 누르세요. 첫 글자가 나오기까지 1~2분 걸릴 수 있습니다."
4. "결과 아래에서 한글(hwpx) · 워드 · PDF 가운데 골라 파일로 받습니다."

## 3. 도구가 없을 때

- 파일을 그대로 게시하는 도구나 기능 선언 도구가 이 대화에 없으면, 코드를 직접 다시 쓰려고 하지 않는다. "이 대화에서는 사이트를 게시할 수 없습니다"라고 한 줄로 알리고, 강사가 만든 사이트 주소를 안내한다: https://claude.ai/artifact/KZ8jbQyiu3qHRkMRhjxe93
- 게시는 됐는데 기능 선언이 실패하면, 실패한 이유를 한 줄로 알리고 선언을 한 번 더 시도한다.

## 4. 게시한 뒤에 사용자가 요청할 수 있는 것

| 요청 | 하는 일 |
|---|---|
| "기관명을 ○○로 바꿔 줘" 같은 0번 값 변경 | CONFIG 블록의 해당 줄만 고쳐 같은 아티팩트에 다시 게시한다. 다시 게시한 뒤 기능 선언이 그대로인지 확인한다 |
| "실행이 안 돼", "기능을 선언해 줘" | 3단계 선언을 다시 넣는다 |
| "링크를 다른 사람에게 주고 싶어" | 공유는 사용자가 사이트 화면의 공유 단추로 직접 한다고 알린다 |
