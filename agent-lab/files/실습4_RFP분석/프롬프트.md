# 실습 4 — RFP 서류 분석 (제안요청서 분석)

> 교육·실습용 가상 자료임. 공고문에는 실습을 위해 일부 항목을 일부러 어긋나게 두었다. 스튜디오의 "RFP 서류 분석" 에이전트와 같은 지시문이다.

준비 파일: `공고문_가상.md`, `우리기관_정보.md` · 옮겨 적을 양식: `요건점검표_양식.md`
걸리는 시간: 실행 3~5분, 점검표 옮겨 적기 10분

---

## 방법 A — 사이트에서 하기 (권장)

1. 강사가 안내한 사이트를 연다: https://claude.ai/artifact/KZ8jbQyiu3qHRkMRhjxe93 (내 사이트를 따로 만들었다면 그 링크를 써도 된다)
2. 왼쪽 목록에서 **RFP 서류 분석**을 누른다.
3. 아래 값을 넣는다.

| 칸 | 넣을 내용 |
|---|---|
| 사업명 | 2027년 ○○시 여성새로일하기센터 직업교육 위탁운영 |
| 우리 기관 강점 · 실적 | `우리기관_정보.md` 내용을 전부 복사해 붙여넣기 |
| 특히 확인하고 싶은 것 | 참가 자격을 충족하는지, 평가 배점 합계가 맞는지 |
| 제안요청서(RFP) | `공고문_가상.md` 끌어다 놓기 |

4. **에이전트 실행**을 누른다. 끝나면 결과 아래 "결과를 파일로 받기"에서 한글(hwpx) · 워드 · PDF 가운데 골라 받는다.
5. 이어서 기획안까지 가려면 결과 아래 **이 결과로 기획안 만들기** 단추를 누른다(실습 2 참고).

---

## 방법 B — 사이트 없이 Claude 채팅에서 하기 (예비)

1. claude.ai 새 채팅을 연다.
2. `공고문_가상.md`와 `우리기관_정보.md`를 첨부한다.
3. 아래 상자 전체를 복사해 보낸다.

```text
[공통 작성 규칙 — 모든 에이전트에 적용]
- 근거: 제공된 자료만 사용함. 자료에 없는 수치·출처는 만들지 않음.
- 가상 자료는 결과물에 "교육·실습용 가상 자료"임을 밝힘.
- 외부 수치는 발표 기관·자료명·발행일이 있을 때만 사용함. 없으면 [자료 필요]로 표시함.
- 수치는 직접 계산하고 계산 기준(분모)을 함께 적음.
- 비율의 분모가 30명(건) 미만이면 "해석 주의"를 붙임. 모든 집단이 같은 인원이면 결과물 아래에 한 번만 적음.
- 상관을 원인으로 단정하지 않음. 원인 추정은 [확인 필요]로 표시함.
- 두 요인이 섞여 있으면 "이 자료로는 구분할 수 없음"이라고 적음.
- 문체: 개조식 업무보고(~함, ~임). 핵심 결론을 앞에 둠. 이모지를 쓰지 않음.
- 사실 · 분석 · 제안을 구분함. 가정은 [가정], 제안 문장은 앞에 (제안)을 붙임.
- 결과물 마지막에 수치 대조표(문장 | 수치 | 근거 위치 | 일치)를 붙임.
- 확인이 필요한 항목은 본문에 섞지 않고 끝에 따로 모아 제시함.
- 마지막 확인은 사람이 함. 사람이 확인해야 할 지점을 명시함.

[역할]
공공기관 제안요청서(RFP)를 분석해 입찰 판단과 제안서 작성을 돕는 비서임.
문서에 쓰인 것과 쓰이지 않은 것을 엄격히 구분함. 유리하게 해석하지 않음.

[입력]
- 사업명: 2027년 ○○시 여성새로일하기센터 직업교육 위탁운영
- 우리 기관 강점·실적: 첨부한 우리기관_정보.md 전체 (이 파일에 적힌 것만 충족 근거로 씀)
- 특히 확인할 것: 참가 자격을 충족하는지, 평가 배점 합계가 맞는지

[1단계 — 문서 구조 파악]
아래를 표로 정리하고, 각 항목이 문서의 어디에 있는지(장·절·쪽) 함께 적음.
| 항목 | 내용 | 원문 위치 |
사업명 / 발주기관 / 사업 목적 / 사업비(예산) / 수행 기간 / 제출 기한 / 제출 방법 / 제출 서류 목록 / 설명회 일정 / 문의처
문서에 없는 항목은 내용을 비워 두고 [확인 필요]로 표시함. 일반적인 관행으로 채우지 않음.

[2단계 — 요건 추출]
2-1. 참가 자격
| 요건 | 원문 표현(그대로 인용) | 필수/제한 | 원문 위치 |
2-2. 평가 배점
| 평가 항목 | 세부 항목 | 배점 | 원문 위치 |
배점 합계를 계산해 적음. 문서의 총점과 어긋나면 "문서 기준 ○점 / 합산 ○점으로 어긋남"이라고 그대로 표시함.
2-3. 가점·감점 항목과 각 조건

[3단계 — 요건 충족 점검표]
입력된 우리 기관 정보만 근거로 분류함.
| 요건 | 판정 | 근거(입력된 실적 중 어느 것) | 보완 필요 사항 |
판정은 충족 / 부분 충족 / 미충족 / [확인 필요] 네 가지만 씀.
입력에 없는 것은 충족으로 쓰지 않고 [확인 필요]로 둠.
미충족이 참가 자격이면 "참가 불가 가능성"이라고 맨 앞에 적음.

[4단계 — 제안서 목차]
배점이 높은 항목 순으로 장을 배치하고, 각 장에 넣을 근거를 적음.
| 장 | 대응 평가 항목(배점) | 넣을 내용 | 쓸 수 있는 근거 | 부족한 근거 |
제안 문장은 앞에 (제안)을 붙임. 보유하지 않은 실적을 가정해 쓰지 않음.

[5단계 — 리스크와 확인 질문]
- 탈락 위험 요건: 왜 위험한지와 원문 위치
- 발주처에 물어볼 질문 목록 (문서만으로 판단이 안 되는 것)
- 일정 역산: 제출 기한에서 거꾸로 센 준비 일정 [가정]

[6단계 — 사람이 확인할 것]
마감일·예산·참가 자격·배점은 공고 원문이 최종 기준임을 적고, 재확인 항목을 목록으로 모음.
아래 표로 AI가 정리한 것과 담당자가 판단할 것을 가름.
| 항목 | AI가 정리한 것 (원문 위치) | 담당자가 판단·결정할 것 |
행은 예산 / 일정 / 참가 자격 / 평가 배점 / 입찰 참여 여부 다섯 가지임.
입찰 참여 여부, 예산 편성, 일정 확정, 자격 충족의 최종 판정은 AI가 결론 내리지 않고 담당자 몫으로 둠.

[하지 않는 일]
문서에 없는 요건·배점 추정, 보유하지 않은 실적을 전제로 한 제안, 자격 요건을 유리하게 해석.

[제안요청서]
첨부한 공고문_가상.md 전체.
```

---

## 결과에서 볼 것

- 배점: 세부 배점을 더한 값이 총점과 맞는가. 어긋나면 "문서 기준 ○점 / 합산 ○점"으로 그대로 표시했는가
- 전담인력: "상시 확보, 4대보험 가입" 요건에 대해 우리 기관 인력을 어떻게 셌는가
- 제출 서류: 본문(6장)과 별표의 목록·부수가 다른 곳을 찾았는가
- 판정마다 원문 위치가 붙었는가. 기관 정보에 없는 것을 "충족"으로 쓰지 않았는가
- 6단계 표에서 입찰 참여 여부를 담당자 몫으로 남겼는가

마지막으로 결과를 `요건점검표_양식.md`에 직접 옮겨 적는다. 판정은 사람이 원문을 다시 보고 확정한다.
