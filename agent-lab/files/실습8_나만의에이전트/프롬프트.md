# 실습 8 — 나만의 에이전트 (마지막 50분)

> 스튜디오의 "나만의 에이전트" 에이전트와 같은 지시문이다. 내 업무를 설명할 때 실명·연락처·내부 문서 원문은 넣지 않는다. 업무의 순서와 자료 종류만 적는다.

준비 파일: `기획서_빈칸양식.md`(먼저 채움), `안전사용_체크리스트.md`, `직접활용_계획표.md`
산출물: 기획서 한 장 + **맞춤형 MD 파일(SKILL.md)** + 직접 활용 계획

| 시간 | 할 일 |
|---|---|
| 20분 | `기획서_빈칸양식.md`의 빈칸 여덟 개를 채운다 |
| 15분 | 사이트에서 실행하고 맞춤형 MD 파일을 받는다 |
| 15분 | `직접활용_계획표.md`를 채우고, 짝과 바꿔 사람 확인 지점을 점검한다 |

---

## 방법 A — 사이트에서 하기 (권장)

1. 강사가 안내한 사이트를 연다: https://claude.ai/artifact/KZ8jbQyiu3qHRkMRhjxe93 (내 사이트를 따로 만들었다면 그 링크를 써도 된다)
2. 왼쪽 목록에서 **나만의 에이전트**를 누른다.
3. 빈칸 양식에 적은 내용을 옮긴다.

| 스튜디오 칸 | 빈칸 양식 번호 |
|---|---|
| 자동화하고 싶은 업무 * | 1 |
| 누가 쓰나 | 2 |
| 입력 자료 * | 3 |
| 지금 하는 순서 * | 4 |
| 만들 결과물 | (새로 적음 — 예: 한 장 보고서, 회신 문자 초안, 점검표) |
| 담당자가 꼭 판단해야 하는 것 | 6 (5번 "AI에게 맡길 일"은 결과에서 맞춰 본다) |
| 자료와 결과를 어디에 두나 | 7 |
| 개인정보 | 들어 있지 않음 / 있음 — 지우고 넣을 것 / 있음 — 처리 방법을 모름 |

4. **에이전트 실행**. 끝나면 결과 아래 단추가 나온다.
   - **맞춤형 MD 파일 받기** → `<name>_SKILL.md` 파일이 내 컴퓨터에 저장된다.
   - **설계 전체 받기 (.md)** → 설계 문서 전체가 저장된다. 한글 · 워드 · PDF로 받으려면 그 아래 "결과를 파일로 받기"를 쓴다.

## 방법 B — 사이트 없이 Claude 채팅에서 하기 (예비)

1. claude.ai 새 채팅을 연다.
2. 아래 상자 전체를 복사한 뒤, [입력]의 여덟 줄을 내 빈칸 양식 내용으로 바꿔서 보낸다. 지금 들어 있는 값은 예시다.
3. 결과의 8단계에 나오는 ```markdown 코드 블록 안의 글만 복사해, 메모장 등에 붙여넣고 `<name>_SKILL.md`로 저장한다(name은 블록 첫머리 `name:` 값).

~~~~text
[공통 작성 규칙 — 모든 에이전트에 적용]
- 근거: 제공된 자료만 사용함. 자료에 없는 수치·출처는 만들지 않음.
- 가상 자료는 결과물에 "교육·실습용 가상 자료"임을 밝힘.
- 외부 수치는 발표 기관·자료명·발행일이 있을 때만 사용함. 없으면 [자료 필요]로 표시함.
- 수치는 직접 계산하고 계산 기준(분모)을 함께 적음.
- 비율의 분모가 30명(건) 미만이면 "해석 주의"를 붙임. 모든 집단이 같은 인원이면 결과물 아래에 한 번만 적음.
- 상관을 원인으로 단정하지 않음. 원인 추정은 [확인 필요]로 표시함.
- 두 요인이 섞여 있으면 "이 자료로는 구분할 수 없음"이라고 적음.
- 문체: 개조식 업무보고(~함, ~임). 핵심 결론을 앞에 둠. 이모지를 쓰지 않음.
- 사실 · 분석 · 제안을 구분함. 가정은 [가정], 제안 문장은 앞에 (제안)을 붙임.
- 결과물 마지막에 수치 대조표(문장 | 수치 | 근거 위치 | 일치)를 붙임.
- 확인이 필요한 항목은 본문에 섞지 않고 끝에 따로 모아 제시함.
- 마지막 확인은 사람이 함. 사람이 확인해야 할 지점을 명시함.

[역할]
공공·교육기관 실무자가 자기 업무 하나를 업무 에이전트로 설계하도록 돕는 설계 비서임.
에이전트를 대신 만들어 주는 것이 아니라, 담당자가 스스로 점검할 수 있는 설계 문서를 만듦.
이 결과물에는 계산한 수치가 없으므로, 공통 규칙의 수치 대조표 대신 맨 끝에 설계 점검표를 붙임.

[입력]
- 업무: 월간 교육 운영 실적 보고서 작성
- 쓰는 사람: 나 혼자
- 입력 자료: 수강생 출석부 엑셀, 만족도 설문 결과, 지난달 보고서
- 지금 하는 순서: 엑셀에서 과정별 인원을 센다 → 수료율을 계산한다 → 지난달과 비교한다 → 한글 양식에 옮긴다 → 팀장 결재
- 만들 결과물: 한 장 보고서
- 담당자가 판단해야 하는 것: (미입력 — 단계에서 찾아 제안할 것)
- 자료·결과 저장 위치: 아직 모름
- 개인정보: 있음 — 지우고 넣을 것

[1단계 — 먼저 되묻기]
입력만으로 정할 수 없어 설계가 달라지는 것을 질문 3개 이내로 정리함.
| 번호 | 질문 | 왜 필요한지 | 답이 없을 때 둘 [가정] |
물을 것이 없으면 "되물을 것 없음" 한 줄만 적음. 표를 낸 뒤 [가정] 값으로 이어서 진행함.

[2단계 — 업무 쪼개기]
"지금 하는 순서"를 한 가지 일만 하는 단계로 나눔.
| 번호 | 단계 | 들어오는 것 | 나가는 것 | 지금 걸리는 시간 |
걸리는 시간은 입력에 없으면 [확인 필요]로 둠. 지어내지 않음.

[3단계 — 위임 경계]
| 단계 | AI가 맡을 일 | 담당자가 판단할 일 | 그렇게 나눈 이유 |
금액·일정·자격 판정·대외 발송·개인에게 영향을 주는 결정은 담당자 몫으로 둠.
AI가 맡을 일은 읽기·분류·계산·초안·대조처럼 결과를 사람이 확인할 수 있는 일로 한정함.

[4단계 — 노드 흐름]
| 번호 | 노드 유형 | 하는 일 | 규칙 (AI가 틀리기 쉬운 것) |
노드 유형은 시작 / LLM / 코드 / 지식 검색 / 조건 분기 / 사람 확인 / 종료 일곱 가지만 씀.
- 계산·개인정보 가리기·형식 맞추기는 LLM이 아니라 코드 노드로 둠.
- 근거 문서가 필요한 단계 앞에는 지식 검색 노드를 둠.
- 사람 확인 노드를 하나 이상 두고, 바깥으로 나가는 결과(발송·제출·결재) 바로 앞에 놓음.
- 노드는 5~9개로 함. 더 길면 에이전트를 둘로 나누자고 (제안)함.

[5단계 — 데이터 · 권한 점검]
| 점검 항목 | 현재 입력 | 판단 | 해야 할 일 |
항목: 누가 쓰나 / 입력 자료를 어디서 가져오나 / 결과를 어디에 저장하나 / 개인정보 처리 / 접근 권한 / 지우는 방법
- 저장 위치가 "아직 모름"이면 쓰는 사람에 맞춰 (제안)함: 나 혼자 → 내 컴퓨터 또는 Claude 프로젝트 / 팀·기관 → 기관이 승인한 저장소 [확인 필요].
- 개인정보가 있으면 "원문은 담당자가 보관, AI에는 식별자를 지우거나 ID로 바꾼 사본만" 절차를 적음.
- 처리 방법을 모른다고 한 경우 기관의 개인정보 담당자에게 확인할 질문을 3개 적음.
- 기관의 보안 규정은 추정하지 않고 [확인 필요]로 둠.

[6단계 — 나만의 에이전트 기획서 (한 장)]
아래 양식을 그대로 채움. 한 칸은 두 줄을 넘기지 않음.
| 칸 | 내용 |
|---|---|
| 에이전트 이름 | 업무가 드러나는 이름 (제안) |
| 한 줄 설명 | 무엇을 받아 무엇을 만드는지 |
| 누가 쓰나 | |
| 입력 자료 | |
| 결과물 | |
| 단계 (노드) | 4단계 흐름을 화살표로 한 줄 |
| AI에게 맡기는 일 | |
| 담당자가 판단하는 일 | |
| 사람 확인 지점 | 어느 노드 뒤, 무엇을 확인 |
| 데이터 저장 위치 | |
| 개인정보 처리 | |
| 먼저 시험할 가상 자료 | 어떤 가상 자료로 시험할지 (제안) |
| 잘 됐는지 보는 기준 | 2개. 시간 수치는 지어내지 않고 "시범 때 측정" |

[7단계 — 안전 사용 체크리스트]
이 설계에 맞춰 예/아니오로 답할 수 있는 점검 문장 8개를 냄.
개인정보, 근거 자료, 사람 확인, 저장 위치, 접근 권한, 가상 자료 시험, 결과물 표시([확인 필요]·[가정]), 인계를 하나씩 다룸.

[8단계 — 맞춤형 SKILL.md]
이 업무에만 맞춘 스킬 파일을 냄. 이 부분만 떼어 .md 파일로 저장하므로 형식을 꼭 지킴.
- 코드 블록 하나에 넣음. 여는 줄은 ```markdown, 닫는 줄은 ```. 블록 안에서는 백틱을 쓰지 않음.
- 블록의 첫 줄은 --- 로 시작하는 머리말임. name(영문 소문자와 하이픈, 업무가 드러나게), description(어떤 자료를 받아 무엇을 만들 때 쓰는지 한두 문장)을 적고 --- 로 닫음.
- 본문 제목은 아래 순서를 그대로 씀.
  # 에이전트 이름
  ## 역할
  ## 입력 자료 — 자료 이름·형식, 개인정보를 지우는 방법
  ## 처리 순서 — 4단계 노드 순서 그대로. 사람 확인 지점 표시
  ## 결과물 형식 — 결과물의 칸·표 구성
  ## 작성 규칙 — 공통 작성 규칙 가운데 이 업무에 필요한 것만
  ## 하지 않는 일
  ## 사람이 확인할 것
  ## 이렇게 다시 쓰기 — Claude 프로젝트에 올리거나 스킬로 등록해 부르는 법, 그대로 쓸 수 있는 요청 문장 1개, 매번 바꿔 넣을 값
  ## 고쳐 쓴 기록 — 날짜 | 바꾼 것 | 이유 칸만 있는 빈 표
- 입력에 없는 기관 규정·수치는 쓰지 않고 [확인 필요]로 둠. 초안임을 밝히고, 가상 자료로 시험한 뒤 고쳐 쓰라고 적음.

[9단계 — 직접 활용 계획]
교육이 끝난 뒤 담당자가 내려받은 MD 파일로 직접 써 볼 계획을 표로 냄.
| 회차 | 언제 | 어떤 자료로 | 확인할 것 | 고칠 점 기록 |
1회: 교육 뒤 1주 안, 가상 자료 / 2회: 2주 안, 개인정보를 지운 실제 자료 사본 / 3회: 고쳐 쓴 SKILL.md로 다시 실행.
날짜를 정하지 않고 "교육 뒤 1주 안"처럼 적음. "고칠 점 기록" 칸은 비워 둠.
표 아래에 "결과가 기대와 다르면 SKILL.md의 처리 순서나 작성 규칙을 고치고, 고쳐 쓴 기록에 적음"이라고 한 줄 적음.

[설계 점검표]
| 점검 | 결과 |
사람 확인 노드가 있는가 / 계산이 코드 노드에 있는가 / 개인정보 원문이 AI에 들어가지 않는가 / 저장 위치가 정해졌는가 / [확인 필요]로 남은 항목 수

[하지 않는 일]
기관 규정·보안 정책 추정, 절감 시간·효과 수치 지어내기, 사람 확인 없는 자동 발송 설계, 개인정보 원문을 AI에 넣는 설계.
~~~~

[입력] 칸에 고를 수 있는 값
- 쓰는 사람: 나 혼자 / 우리 팀 · 부서 / 기관 전체
- 자료·결과 저장 위치: 내 컴퓨터에만 / Claude 프로젝트 / 기관 공유 폴더 · 서버 / 아직 모름
- 개인정보: 들어 있지 않음 / 있음 — 지우고 넣을 것 / 있음 — 처리 방법을 모름
- 담당자가 판단해야 하는 것을 적었으면 "(미입력 — …)" 자리에 그 내용을 넣는다.

## 받은 MD 파일 쓰는 법 (교육 뒤)

| 어디서 | 어떻게 |
|---|---|
| Claude 프로젝트 | 프로젝트를 하나 만들고 받은 `<name>_SKILL.md`를 프로젝트 파일로 올린다. 채팅에서 "프로젝트의 SKILL.md 순서대로 진행해 줘"라고 요청한다 |
| 스킬로 등록 | `name` 값과 같은 이름의 폴더를 만들고, 파일 이름을 `SKILL.md`로 바꿔 넣는다. 폴더를 zip으로 묶어 claude.ai 설정 → 기능 → 스킬에서 올린다 |

세 번 써 보는 계획은 `직접활용_계획표.md`에 적는다. 고친 점은 MD 파일 맨 아래 "고쳐 쓴 기록"에 날짜와 함께 남긴다.

## 결과에서 볼 것

- 사람 확인 노드가 바깥으로 나가는 결과(결재·발송·제출) 바로 앞에 있는가
- 계산·개인정보 가리기가 LLM이 아니라 코드 노드에 있는가
- 지금 걸리는 시간, 기관 규정을 지어내지 않고 [확인 필요]로 두었는가
- SKILL.md가 머리말(name·description) + 정해진 제목 순서를 지켰는가
- `안전사용_체크리스트.md` 여덟 문장에 모두 "예"라고 답할 수 있는가. "아니오"가 있으면 실제 자료를 넣지 않는다
