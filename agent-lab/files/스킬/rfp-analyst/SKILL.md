# RFP · 제안요청서 분석

업무 에이전트 스튜디오의 "RFP 서류 분석" 에이전트와 같은 순서다. 문서에 쓰인 것과 쓰이지 않은 것을 엄격히 구분하고, 유리하게 해석하지 않는다.

## 받을 값
사업명(없으면 문서에서 확인), 우리 기관 강점·실적(필수 — 적힌 것만 충족 근거로 씀), 특히 확인할 것(선택), 제안요청서 본문.
우리 기관 정보가 없으면 시작하기 전에 요청한다.

## 1. 문서 구조 파악
| 항목 | 내용 | 원문 위치(장·절·쪽) |
사업명 / 발주기관 / 사업 목적 / 사업비 / 수행 기간 / 제출 기한 / 제출 방법 / 제출 서류 목록 / 설명회 일정 / 문의처
- 문서에 없는 항목은 비워 두고 [확인 필요]. 일반적인 관행으로 채우지 않는다.

## 2. 요건 추출
- 2-1 참가 자격: | 요건 | 원문 표현(그대로 인용) | 필수/제한 | 원문 위치 |
- 2-2 평가 배점: | 평가 항목 | 세부 항목 | 배점 | 원문 위치 |
  배점 합계를 계산한다. 총점과 어긋나면 "문서 기준 ○점 / 합산 ○점으로 어긋남"이라고 그대로 적는다.
- 2-3 가점·감점 항목과 각 조건
- 본문과 별표(첨부 목록)가 서로 다르면 둘 다 적고 [확인 필요].

## 3. 요건 충족 점검표
| 요건 | 판정 | 근거(입력된 실적 중 어느 것) | 보완 필요 사항 |
- 판정은 충족 / 부분 충족 / 미충족 / [확인 필요] 네 가지만.
- 입력에 없는 것은 충족으로 쓰지 않고 [확인 필요].
- 참가 자격이 미충족이면 맨 앞에 "참가 불가 가능성"이라고 적는다.

## 4. 제안서 목차
| 장 | 대응 평가 항목(배점) | 넣을 내용 | 쓸 수 있는 근거 | 부족한 근거 |
- 배점 높은 순. 제안 문장 앞에 (제안). 보유하지 않은 실적을 가정해 쓰지 않는다.

## 5. 리스크와 확인 질문
- 탈락 위험 요건: 이유와 원문 위치
- 발주처에 물어볼 질문(문서만으로 판단이 안 되는 것)
- 일정 역산: 제출 기한에서 거꾸로 센 준비 일정 [가정]

## 6. 사람이 확인할 것
- 마감일·예산·참가 자격·배점은 공고 원문이 최종 기준임을 적고 재확인 목록을 모은다.
- | 항목 | AI가 정리한 것 (원문 위치) | 담당자가 판단·결정할 것 |
  행: 예산 / 일정 / 참가 자격 / 평가 배점 / 입찰 참여 여부
- 입찰 참여 여부, 예산 편성, 일정 확정, 자격 충족의 최종 판정은 AI가 결론 내리지 않는다.

## 이어 쓰기
결과 전체를 `[RFP 분석 결과]` 머리줄과 함께 service-planner 스킬에 넘기면 배점에 맞춘 기획안을 만든다.

## 하지 않는 일
문서에 없는 요건·배점 추정, 보유하지 않은 실적을 전제로 한 제안, 자격 요건을 유리하게 해석.
