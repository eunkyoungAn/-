# 고객 데이터 → 신규 서비스 기획

업무 에이전트 스튜디오의 "기획안 작성" 에이전트와 같은 순서다.

## 받을 값
기관명, 대상 고객, 산출 형식(서비스 기획서 / 한 장 보고서 양식), 제약 조건(인력·예산·일정. 없으면 [가정]).

## 0. RFP 분석 결과 연결 (있을 때만)
자료에 "[RFP 분석 결과]"가 있으면 먼저 수행한다. 없으면 건너뛴다.
- 배점이 높은 항목 3개와 미충족·[확인 필요] 요건을 표로 옮긴다. RFP 분석 결과에 없는 요건·배점은 만들지 않는다.
- 3단계 기획서 각 항목 옆에 "대응 평가 항목(배점)"을 적는다.
- 고객 데이터가 없으면 1~2단계는 [자료 필요]로 두고, 올릴 자료(설문·문의 기록)를 안내한 뒤 3단계는 뼈대만 낸다.

## 1. 고객 불편 찾기
- 선택형 문항: 상위 항목과 비율(기준 인원 포함), 집단별(운영형태·연령 등) 비교
- 문의 기록: 유형별 건수, 평균 처리 시간, 시간대별 차이(접수 시각 기준. 업무 외 시간 = 20시 이후, 다르게 나누면 기준을 적음)
- 자유 의견: 주제별로 묶고 주제마다 대표 문장 2개를 그대로 인용
- 기준 인원이 30명(건) 미만이면 "해석 주의"

## 2. 문제 정의
| 후보 문제 | 영향받는 사람 수(관련 항목 선택 인원 / 전체 응답자) | 불편 강도(쓴 수치를 명시) | 우리 조직이 해결 가능한지 |
- 후보 3개를 비교하고 하나를 추천한다. 해결 가능성에 자료가 없으면 [확인 필요]로 두고 마지막에 확인 질문(인력·예산·담당 부서)을 한다.
- "누가 / 언제 / 무엇 때문에 / 무엇을 못 하는가" 한 문장으로 정의한다.

## 3. 기획서
| 항목 | 기준 |
|---|---|
| 서비스명 | 한 줄 이름 + 한 줄 설명 |
| 기획 배경 | 1단계 수치 2~3개 |
| 대상 고객 | 데이터 속 집단 기반 페르소나 1명 ([가정]) |
| 문제 정의 | 2단계 문장 + VOC 인용 |
| 핵심 기능 | 3개 이내(MVP). 문제의 원인·장면 하나씩과 연결 |
| 운영 방식 | 사람이 하는 일 / AI가 하는 일 / 사람이 승인하는 지점 |
| 성과 지표 | 2~3개. 기준값은 데이터에서, 목표값은 [가정]. 기준값이 없으면 "시범 시작 때 측정" |
| 시범 운영 | 대상·규모·기간·단계 [가정] |
| 위험과 대응 | 개인정보, 결과 품질, 담당자 업무 부담 |
| 필요 자원 | 인력·도구·예산 [가정] 또는 [확인 필요] |
- 한 장 보고서 양식으로 요청하면: 개요 = 서비스명 + 문제 / 실행계획 = 시범 계획 / 분석1~3 = 문제 근거 / 해결방안 = 기능 + 운영 / 결론 = KPI와 (단기)·(중장기)

## 4. 결정권자 관점 검토
데이터로 뒷받침되지 않는 주장, 과소평가된 실행 부담(인력·비용), 더 작은 규모로 먼저 시험할 방법.

## 5. 수치 대조표
| 문장 | 수치 | 근거 위치 | 일치 |

## 하지 않는 일
근거 없는 기대 효과·시장 규모, 가정을 사실처럼 쓰기, 개인정보를 AI 도구에 넣는 운영안.
