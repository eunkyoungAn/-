# 업무지시서: 커리어캐쳐 AI 취업 준비 서비스 링크드인 소개글

- 접수일: 2026-11-01
- 주제 링크: https://eunkyoungan.github.io/-/career-hub/#services (이 세션에서 사이트 접속 불가 → 저장소 `career-hub/` 소스와 저장소 기록으로 대체)
- 사용자 추가 지시(작업 중 도착): "이 내용을 바탕으로 링크드인에 서비스를 만들고 소개하는 글을 적고 싶어"

## 목적·대상·산출물
- 목적: 안은경(커리어캐쳐 코치)이 취업 준비 AI 서비스 3종을 직접 만든 과정과 서비스를 링크드인에서 소개한다.
- 대상: 링크드인 독자 — 교육·취업지원 현업(대학 일자리센터, 교육기관, 코치·강사), 채용·HR 담당자, 취준생.
- 산출물: 링크드인 게시글 1편(한국어, 1인칭, 코치가 직접 쓴 톤). 네이버 블로그 글이 아님.
- 형식 기준: 첫 2~3줄 훅(더 보기 전에 보이는 부분), 짧은 문단, 본문 약 1,200~1,800자(상한 3,000자), 해시태그 3~5개, 링크 안내, 마지막에 질문이나 행동 유도 1개.

## 가정 (되묻지 않고 기록)
1. 서비스 3종은 서비스 허브 `#services` 구역의 내용 그대로다: 01 기업·경험 찾기, 02 AI 자기소개서 작성, 03 AI 포트폴리오 작성.
2. "만들고"는 코치가 이 서비스들을 직접 기획·제작했다는 의미로 쓴다. 단, 제작 동기·기간·사용자 수·성과는 사용자가 알려주지 않았으므로 지어내지 않는다. 저장소에서 확인되는 사실만 쓰고, 나머지는 `[확인 필요]`로 표시한다.
3. 서비스는 본인 Gemini API 키가 필요하고 키는 서버에 저장되지 않는다(허브 문구 기준). 무료·회원가입 불필요도 허브 문구 기준.
4. 코치명은 안은경, 브랜드는 커리어캐쳐(CareerCatcher). 링크드인 글에서도 첫 등장 시 한·영 병기.
5. 개인정보·학생 정보는 넣지 않는다.

## 팀별 지시
1. 리서치팀 → `01_research.md`: `career-hub/`(index.html, app.js, styles.css), `portfolio-builder/`, `apps-script/`, `PROVENANCE.md`, `README.md`, `docs/`, 기존 글(`posts/2026-10-06-ai-resume-interview`, `posts/2026-10-15-ai-era-job-seeker`, `office/20261024_포트폴리오빌더`)에서 서비스 3종의 기능·흐름·제작 과정에서 확인되는 사실을 정리. 사실마다 파일 경로 근거 표기, 확인 못 한 것은 '미확인'.
2. 기획팀 → `02_plan.md`: 훅, 서사 구조(문제 → 만든 이유 → 3종 소개 → 만들며 지킨 원칙 → 질문), 길이 배분.
3. 작성팀(`office-writer`) → `03_draft.md`: 링크드인 게시글 + 해시태그 + 첫 댓글용 문구.
4. 검수팀 → `04_review.md`: 사실 확인(근거 없는 성과·숫자 금지), 톤, 링크드인 형식 점검.
