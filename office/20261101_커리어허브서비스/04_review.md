- 인사 "취업 코칭을 하는 안은경": 브리프에 코치로 명시되어 있어 문제 없음.

## 5. 수정 지시

### [필수 수정]
1. 훅 단정 처리. 훅 아래(또는 위)에 `[확인 필요: 현장에서 이 말을 가장 자주 들었는지, 다른 표현이 맞는지]`를 붙인다. 안전한 대체안: "자기소개서 컨설팅에서 이런 말을 자주 듣습니다."(사용자 확인 후), 또는 계획서 훅 C("취업 준비 AI 도구를 만들며 가장 크게 배운 건 기능이 아니라 순서였습니다")로 교체. C는 제작 범위 동사 확인에 의존한다.
2. 원칙 1의 이유 문장 "서류는 결국 본인이 설명해야 하는 글이기 때문입니다"와 원칙 2의 "남의 키를 맡아 두지 않는 쪽을 택했습니다"를 삭제하거나 `[확인 필요: 이유(본인 설계 의도)]`로 바꾼다. 근거가 있는 문장만 남기려면 원칙 1은 "없는 경험은 지어내지 않고, 입력하신 경험에서 출발하도록 안내합니다.", 원칙 2는 "API 키는 서버에 저장하지 않습니다. 본인의 API 키로 사용합니다."까지.
3. 원칙 1 "입력한 경험에서만 출발합니다"를 보장형에서 안내형으로 낮춘다. 예: "없는 경험은 지어내지 않고 입력한 경험에서 출발하도록 안내합니다." 그리고 02의 "없는 경험을 지어내는 것은 쓰면 안 되는 경우" 명시(01 ②)는 사실이므로 이를 근거로 쓴다.
4. 첫 댓글(③)과 원칙 2의 "본인의 Gemini API 키가 필요합니다/키로 사용하고"를 고친다. 제안 문구: "AI 실행에는 본인의 API 키가 필요합니다(Gemini 무료 키 등). 03은 키 없이 프롬프트를 복사해 ChatGPT·Claude 웹에 붙여넣는 방법도 있습니다. AI 사용 한도와 요금은 선택한 AI에 따릅니다." 01이 사용자 키를 쓰는지는 01 ②에 없으므로 `[확인 필요: 01도 본인 키를 쓰는지]`를 달거나 "서비스에 따라"로 쓴다.
5. 흐름 수리. "이 서비스들을 [동사]" 문장은 서비스를 소개하기 전에 나와 지시어가 가리킬 대상이 없다. 다음처럼 바꾼다. "그래서 경험 찾기 → 자기소개서 → 포트폴리오로 이어지는 도구 세 가지를 [확인 필요: 동사 후보] ." 그 뒤에 동기 문장, 이어서 "서비스는 세 가지입니다."로 연결한다. 동기 문장은 별도 줄로 두되 앞 문장과 이어 읽히게 한다.
6. 길이 보강(아래 6절). 최종본 약 1,000자를 1,300자 안팎으로 늘린다.
7. 03_draft ⑤ 글자 수 메모를 고친다. 후보 선택 최종본은 약 1,000자(해시태그 제외), [확인 필요] 포함 전체는 약 1,350자로 정정.

  1. 배운 점을 2~3문장으로 확대(+70~100자). 후보 중 하나에 "그래서 도구를 만들 때도 문장 생성보다 질문 순서를 먼저 정했습니다" 같은 연결 문장은 동기 확인 후에만.
  2. 서비스 소개에 근거 있는 기능 한 줄씩(+약 120자). 01: "경험카드 1개, 자기소개서 초안 1개, 면접 질문 10개를 이메일로 받습니다."(01 ②) / 02: "작업은 저장·불러오기 파일로 옮길 수 있습니다."(01 ②) / 03: "결과는 노션형 미리보기로 보고, HTML 저장이나 노션용 복사로 가져갑니다."(01 ②). 03의 노션 양식 순서는 "퍼플커리어 양식"이라는 외부 명칭이 있어 쓰기 전에 사용자에게 확인.
  3. 문제 단락에 사용자 경험 한두 문장(+60~100자). 이는 사용자가 쓰는 부분이라 초안에서는 [확인 필요]로 자리만 잡는다.
- 만약 추가를 하지 않으면 1,200자 미달로 계획서 기준을 못 맞춘다. 브리프 형식 기준은 "약 1,200~1,800자"이므로 약 1,000자도 링크드인 게시글로 문제는 없지만, 지시서 기준 충족을 위해 위 보강을 권장한다. 사용자가 짧은 글을 선호하면 이 기준 미달을 사용자가 수용하는 것으로 처리하고 알린다.
