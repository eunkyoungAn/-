# 01_research — 커리어캐쳐 AI 포트폴리오 빌더 (작성일 2026-10-24)

## ① 핵심 요약
- 빌더는 노션 포트폴리오 양식 순서(Contact → About me → Skills → AI Competency → Projects → Experiences → Education → Language·Other)로 입력받아, AI가 입력 내용을 빠짐없이 다듬어 완성본(미리보기 + 단일 HTML 파일)을 만드는 무료 웹 도구.
- AI 완성 방식은 2가지: (A) API 키 붙여넣기(Gemini 무료 / Claude 유료)로 버튼 한 번 (B) 키 없이 프롬프트 복사 → ChatGPT·Claude 웹에 붙여넣기 → 답변을 다시 붙여넣기.
- 개인정보: 서버 저장 없음, 입력은 이 브라우저(localStorage)에만 임시 저장, API 키는 저장 안 함, 이메일·연락처는 AI 프롬프트에서 제외. 단 그 외 입력(이름·학교·프로젝트 등)은 AI에 전달됨.
- 채용 쪽 일반론: 신입 포트폴리오는 "결과 크기"보다 "문제 → 과정 → 본인 역할 → 근거"를 본다는 의견이 다수이나, 채용담당자 대상 공식 설문(포트폴리오 전용)은 확인하지 못함.
- 출처 한계: 웹 검색 스니펫만 확인했고 원문 페이지 열람(WebFetch)은 네트워크 오류로 실패. 아래 외부 근거는 모두 "검색 결과 요약 기준"임.

## ② 주요 발견 — 빌더가 실제로 하는 일 (사실, 파일 근거)

### 1. 입력 단계 (index.html 화면 순서 = 노션 양식 순서)
README는 7개(Contact·About me·Skills·AI 역량·Projects·Experiences·Education)로 적고, 실제 화면에는 8번째 "Language · Other"가 더 있음. (글에서는 "7단계+어학·기타" 또는 "노션 양식 순서"로 쓰는 것이 안전)
1. Contact·기본 정보: 이름, 지원 직무, 이메일, 연락처, 링크(블로그·깃허브·링크드인·인스타), M365 공고 불러오기(선택), 채용공고 핵심 내용(선택, 키워드 매칭용)
2. About me: 강점·관심사를 편하게 서술
3. Skills: 협업 툴 / 기술 스택과 활용 수준
4. AI Competency (활용 → 검증 → 성과): 사용 AI 도구·숙련도, AI로 일하는 방식이 바뀐 사례(전/후), 검증·윤리 원칙, AI 관련 학습·자격·프로젝트(선택)
5. Projects (성과 좋은 순서로, 여러 개 추가 가능): 프로젝트명, 작업기간, 요약(무엇을·왜), 인원/나의 역할·기여도, 구현·분석 내용과 사용 기술, 성과(숫자로), 문제해결 과정과 배운 점(문제→원인→시도→결과), AI 활용과 검증(선택)
6. Experiences (동아리·인턴·경력 3~4개): 이름, 진행기간, 소개와 맡은 일·성과
7. Education: 학교·기관명, 기간, 전공·과정명
8. Language · Other: 어학, 기타(자격증·수상·봉사)
- 필수 확인: 지원 직무 + 프로젝트 1개 이상이 없으면 "지원 직무와 프로젝트 1개 이상은 적어 주세요" 안내 후 진행 불가. 입력칸 글자 수 제한(한 줄 200자, 긴 칸 2000자).
- 안내 가이드(guide)의 팁: 성과 칸은 "전 → 후 숫자", 문제해결 칸은 "문제 → 원인 → 해결 → 결과" 순.

### 2. AI 자동 완성 방식 2가지
- (A) 키 방식 "⚡ AI 자동 완성 켜기": Google Gemini(무료, aistudio.google.com/apikey에서 카드 등록 없이 발급, 하루 사용 한도 있음) 또는 Claude(유료) 선택. Gemini 모델은 Flash-Lite(기본, 더 많이 생성) / Flash(품질 우선, 한도 적음) 선택, 한도·모델 문제 시 다른 모델로 자동 재시도. 키 입력 시 배지가 "✓ 연결됨". 결과가 실시간 스트리밍으로 우측에 표시, 중단 버튼 있음, 3분 무응답 시 자동 중단. 가이드 FAQ: 생성 1회에 약 5천~1만 토큰, 무료 키는 한도 내 0원.
- (B) 키 없는 방식: [포트폴리오 완성하기] → 프롬프트 자동 복사(복사 실패 시 직접 선택) → ChatGPT 또는 Claude 웹에 붙여넣기 → AI가 "답한 글"("# 직무 | 이름 포트폴리오"로 시작)을 빌더 우측 칸에 붙여넣기 → [결과 적용하기] → [HTML 저장]. 프롬프트 자체를 붙여넣으면 경고 표시.
- 참고(코드상 추가 경로): Claude 아티팩트 환경에서 열면 내장 AI(`window.claude.use("sample")`)로 키 없이 생성하는 분기가 있음. 일반 독자용 설명에서는 불필요(추정: 코치의 Claude 환경용).

### 3. 예시 직무 목록 ([예시로 채우기], 9종)
데이터 분석 / 백엔드 개발 / 프론트엔드 / UX·UI 디자인 / 서비스 기획·PM / 디지털 마케팅 / B2B 영업 / 인사(HR) / M365 엔지니어. 예시 속 이름·학교·수치는 가상 데이터(예: example.com 주소, "한국대학교").
- M365 신입 공고 불러오기(M365 수료자용, 4건): 씨앤토트 M365 엔지니어(신입) / 소프트피플코리아 M365·AD·Exchange 기술지원 / 에이피드 M365·EMS 엔지니어 / 에이스엔지니어링 사내 IT 운영담당자. 선택하면 지원 직무와 공고 요약이 채워지고 "실제 지원 전 원문에서 모집 상태를 확인하세요" 안내. (공고 마감·상태는 변동 → 블로그에 특정 회사 공고를 넣는 건 비추천. 씨앤토트 표기 마감 2026-10-31, 오늘 기준 임박)

### 4. 결과물 형태
- 우측 노션형 미리보기. 출력 구조(프롬프트에 고정): 제목 "# 직무 | 이름 포트폴리오" → 한 줄 자기소개 → About me → Skills(Collaboration & Tools / Tech Stack) → AI Competency(도구·워크플로·성과 전후·검증·윤리 표) → Projects(프로젝트마다 핵심 표 + "상세 내용 보기" 접기) → Experiences 표 → Education 표 → Language → Other.
- 성과 숫자는 하이라이트, 키워드는 굵게. 프로젝트는 성과 좋은 순, 경험은 직무 연관 높은 순 정렬.
- 저장: [HTML 저장] → 파일명 "직무_이름.html"(예: 디지털마케터_김공순.html), 더블클릭하면 브라우저에서 열림, 인쇄(Ctrl+P) → PDF 가능. [노션용 복사]로 노션에 붙여넣기도 가능. (Word/PDF 직접 저장 기능은 없음, PDF는 브라우저 인쇄 이용)
- "🔍 컨설턴트 피드백"(보완하면 좋은 점 3가지)이 본문과 따로 표시되며, 저장하는 HTML에는 포함되지 않음. [피드백 복사]로 따로 보관.
- 상태 줄: 입력 항목이 완성본에 빠졌는지 점검("빠진 항목: ..."), 토큰 사용량 표시. 빠지면 다시 생성 안내.
- 완성 예시(sample/): 디지털 마케터 | 김공순 포트폴리오(가상 인물). 이메일·연락처는 "[보완 필요: 이메일]"로 표시.

### 5. 개인정보 처리
- 화면 안내문: "입력 내용은 서버에 저장하지 않고 이 브라우저에만 임시 저장돼요. 이메일·연락처는 AI에 보내지 않아요. 공용 PC에서는 사용 후 [모두 지우기]". README 동일.
- 코드 확인: 입력은 localStorage("pc-pf2")에 자동 저장, 프롬프트 생성 시 email·phone 삭제, 완성본의 [[EMAIL]]/[[PHONE]] 자리는 브라우저에서 사용자가 입력한 값으로 치환(AI에 전달 안 됨). API 키는 저장 코드 없음(탭 닫으면 사라짐). 보안 정책(CSP)상 외부 통신은 generativelanguage.googleapis.com(Gemini), api.anthropic.com만 허용.
- 주의 문구: 무료 Gemini는 입력 내용이 구글 서비스 개선에 쓰일 수 있음 → 이메일·연락처는 보내지 않는 구조. 가이드: 이메일·연락처 외 나머지 입력은 AI 작성에 쓰이며, 실명 대신 이니셜 사용 가능. 키는 공유 금지.
- 글에서 "개인정보가 전혀 AI로 안 간다"고 쓰면 오류. 정확한 표현은 "이메일·연락처만 제외, 나머지는 AI가 읽음".

### 6. 한계 / 주의점 (글에 정직하게 쓸 것)
- 입력에 없는 사실·수치는 만들지 않도록 프롬프트에 규칙이 있으나(없으면 "[보완 필요: ...]" 표시), AI 결과의 완전성·정확성은 보장 불가 → 사용자가 확인해야 함. 교육 프로젝트를 경력으로, 수료를 자격으로 바꾸지 않는 규칙도 있음.
- 빌더가 대신 만들어 주지 못하는 것: 프로젝트 경험 자체, 실제 숫자. "입력한 것을 정리·강조"하는 도구.
- 무료 Gemini는 하루 한도·혼잡 시 1분 이상 지연·429 오류 가능. 출력이 길어 중간에 끊길 수 있음(재시도 안내).
- 이메일·연락처는 완성본에 직접 넣어야 할 수 있음(키 없는 방식에서는 안내 문구로 [[EMAIL]], [[PHONE]] 직접 입력).
- 결과가 HTML 한 파일이라 채용 사이트가 PDF/PPT만 받는 경우 인쇄→PDF 변환 필요. 링크 호스팅은 사용자가 따로 해야 함.
- 채용 사이트별 제출 양식 대응, 디자인 작업물(이미지) 업로드 기능 없음(코드에 이미지 입력 없음; 디자인 직무 시각 포트폴리오엔 부족, 추정).
- 가이드의 화면 이미지는 "실제 화면을 단순화한 예시"라고 명시되어 있음(실제 화면과 문구 다를 수 있음).
- AI 모델명·한도는 수시로 바뀜(코드에 gemini-2.5-flash(-lite) 등 지정). 글에 모델명·무료 한도 수치 고정 표기는 피하기.
- 미리보기 상태 문구 "무료 한도 내 0원"은 Gemini 무료 키일 때만.

## ③ 통계·사례 — 신입 포트폴리오 채용 관점 (출처 4건, 모두 검색 결과 요약 기준)
※ 원문 페이지 열람 실패(네트워크 차단). 아래는 검색 엔진 요약에 근거하며, 수치는 직접 확인 못 한 항목은 "미확인" 처리.

1. "무엇을 했다"가 아니라 "왜·어떻게·그래서 무엇을 발견했나"
   - 근거: 취업 Q&A·포트폴리오 블로그 다수에서 나열식 정리를 흔한 실수로 지적(분석은 했는데 왜 했는지·비즈니스 의미가 없음). 개인 블로그·Q&A 의견이며 표본 조사 아님.
   - 출처: 브런치 "maven" 글(https://brunch.co.kr/@maven/485), 코멘토 직무 Q&A(https://comento.kr/job-questions/모든회사/모든직무/포트폴리오_이력_내용_오기입-605785). 작성 연도 미확인.
2. 신입은 결과 규모보다 과정(타깃·전략 선택 이유·본인 실행)과 본인 역할을 본다
   - 근거: 코멘토 마케팅 직무 Q&A 답변(개인 멘토 의견, 문제→전략→실행→성과 순 정리·수치 제시 권장). 서비스기획 PM 포트폴리오 평가 도구 글(GPTers)은 데이터·리서치 등 객관적 근거 사용 여부, 팀 프로젝트에서 본인 역할·기여도 명확성을 평가 항목으로 둠.
   - 출처: https://comento.kr/job-questions/모든회사/마케팅/포트폴리오_관련 질문-634980 , https://www.gpters.org/llm-service/post/aiof-residents-2nd-personal-dn7StdehuzNNF4Q (연도 미확인)
   - 빌더 연결: 기여도(%)·역할 칸, 문제→원인→시도→결과 칸이 이 포인트와 맞물림(사실: 입력 항목에 존재).
3. 회사에 어떤 가치를 줬는지 보이지 않는 샘플, 그리고 정리 안 된 구성이 대표적 실수
   - 근거: 광고·마케팅·인터랙티브·디자인 분야 임원 대상 설문 결과를 다룬 USF(University of South Florida) 커리어센터 블로그, 2023-08-21. 검색 요약상 "회사에 제공한 가치를 보여주지 않는 샘플"이 1위, "비체계적 구성"이 2위. 표본 수·세부 비율은 미확인(원문 열람 실패). 디자인·마케팅 분야 한정이므로 모든 직무에 일반화 금지.
   - 출처: https://careers.usf.edu/blog/2023/08/21/survey-reveals-most-common-portfolio-mistakes-among-interactive-design-and-marketing-professionals/
4. 링크·접근성 같은 기본 실수: 비공개 링크, 로그인 상태에서만 열리는 링크, 깨진 링크/첨부 누락
   - 근거: 취업 Q&A 답변(로그아웃·시크릿 창에서 열리는지 확인 권장), 해외 디자인·개발 블로그(깨진 데모·누락 첨부는 신뢰도 하락). 모두 개인·업체 의견.
   - 출처: 코멘토 Q&A(위 1번 링크), https://www.pixpa.com/blog/mistakes-to-avoid-in-ui-ux-design-portfolio , https://lyrid.io/post/5-critical-software-engineer-portfolio-mistakes-that-junior-developers-are-making (연도 미확인)
   - 빌더 연결: 결과가 HTML 한 파일이므로 호스팅/공유 시 공개 여부와 열림 확인은 사용자 몫(빌더가 해결해 주지 않음).
5. (보조) 신입 채용 일반: 기술 나열보다 구체적 사례가 중요
