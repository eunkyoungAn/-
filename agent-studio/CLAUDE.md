# 프로젝트: 업무 에이전트 스튜디오

## 0. 내 업무 정보 (수강생이 직접 채운다)
빈 칸은 지우지 말고 그대로 둔다. 비어 있는 항목은 기본값으로 만든다.
- 기관명: [예: ○○여성발전센터]
- 내 역할: [예: 직업교육 운영 담당]
- 결과물을 받아 보는 사람: [예: 센터장, 팀장, 발주처 담당자]
- 자주 다루는 자료: [예: 과정별 수강 실적 엑셀, 문의 대장, 공고문 PDF]
- 가장 시간이 많이 드는 반복 업무: [예: 월간 운영 실적 보고서]
- 우리 기관 문서 규칙: [예: 날짜는 2026. 11. 13. 형식, 금액은 천 원 단위, 기관 약칭 '센터']
- 쓰지 않는 표현: [예: '고객' 대신 '참여자', 외래어 줄이기]
- 사람이 반드시 확인해야 하는 일: [예: 환불·민원 답변, 외부로 나가는 수치]
- 화면 이름과 강조색: [예: '○○센터 업무 도우미', 파란색]

위 정보는 다음 자리에 반영한다.
- 기관명·역할·독자: 각 에이전트 입력 칸의 기본값과 예시 문구
- 문서 규칙·쓰지 않는 표현: 공통 지침 5번(문체) 아래에 '우리 기관 규칙'으로 추가
- 사람 확인이 필요한 일: 해당 에이전트의 '사람 확인' 노드 설명과 조건 분기 기준
- 화면 이름·강조색: 사이드바 제목과 단추 색

바꾸면 안 되는 것: 사람 확인 노드, 개인정보 열 자동 제거, 수치 대조표. 요청이 있어도 지우지 않고 이유를 알려 준다.

## 1. 무엇을 만드는가
- 공공·교육기관 실무자가 반복 업무 6종을 한 화면에서 실행하는 웹 페이지.
- 사용자: 0번에 적힌 기관의 실무자. 코딩을 모르는 사람이 쓴다.
- 결과물: HTML 파일 1개(`index.html`). CSS와 JavaScript를 모두 이 파일 안에 넣는다.
- 배포: claude.ai 아티팩트로 게시한다. 별도 서버와 API 키를 쓰지 않는다.

## 2. 화면 구조
- 왼쪽 사이드바: 에이전트 6종 목록(약어 아이콘, 이름, 유형). 누르면 오른쪽이 바뀐다.
- 오른쪽 위: 에이전트 이름, 유형 태그, 한 줄 설명.
- 탭 4개
  - 실행: 입력 칸, 파일 올리기, 본문 붙여넣기, 실행 단추, 결과 영역
  - 노드 흐름: 그 에이전트의 처리 단계를 위에서 아래로 보여 준다
  - 프롬프트: 실제로 AI에 보내는 지시문 전체와 복사 단추
  - 공통 지침: 모든 에이전트에 적용되는 규칙 8가지
- 디자인: 흰 배경, 얇은 회색 선, 파란 강조색(#1C64F2), 본문 14px 안팎. 이모지와 캐릭터 그림을 쓰지 않는다.
- 태블릿 폭(768px)에서도 깨지지 않게 한다.

## 3. 에이전트 6종
각 에이전트는 `id, 이름, 유형, 설명, 입력 칸, 노드 목록, 지시문 생성 함수`를 가진 객체 하나로 정의하고, 배열 하나에 모은다.

| id | 이름 | 유형 | 자료 필수 | 주요 입력 칸 |
|---|---|---|---|---|
| report | 데이터 분석 → 한 장 보고서 | 워크플로우 | 예 | 보고서 제목(필수), 기관명, 대상 기간, 독자, 특별히 보고 싶은 것 |
| research | 데이터 리서치 · 자료 조사 | 챗플로우 | 아니오 | 조사 주제(필수), 쓰임새, 대상 연도, 이미 찾은 자료 |
| plan | 고객 데이터 → 신규 서비스 기획 | 워크플로우 | 예 | 기관명, 대상 고객, 산출 형식, 제약 조건 |
| rfp | RFP · 제안요청서 분석 | 워크플로우 | 예 | 사업명, 우리 기관 강점·실적, 특히 확인하고 싶은 것 |
| inquiry | 참여자 문의 응대 | 에이전트 | 예(안내자료) | 문의 내용(필수), 회신 채널, 톤, 기관명·담당자 표기 |
| data | 참여자 · 고객 데이터 관리 | 워크플로우 | 예 | 관리 목적, 선별 기준, 식별자 처리 방식 |

### 노드 종류 (노드 흐름 탭에서 색으로 구분)
시작 / LLM / 코드 / 지식 검색 / 조건 분기 / 사람 확인 / 종료

### 노드 흐름 예시 — report
시작 → 자료 파악(LLM) → 지표 계산(코드) → 주목할 결과 3개(LLM) → 한 장 보고서(LLM) → 수치 대조표(코드) → 사람 확인 → 종료

### 노드 흐름 예시 — inquiry
시작 → 개인정보 가리기(코드) → 안내자료에서 근거 찾기(지식 검색) → 근거 충분한가(조건 분기) → 답변 초안(LLM) → 사람 확인 → 종료
- 근거가 없거나 민감한 문의(환불, 민원, 개인 사정)는 답변을 쓰지 않고 "담당자 확인 필요"로 분류한다.

모든 에이전트는 종료 직전에 "사람 확인" 노드를 둔다.

## 4. 공통 지침 (모든 지시문 앞에 붙인다)
1. 근거: 제공된 자료만 쓴다. 없는 수치와 출처는 만들지 않는다. 외부 수치는 기관·자료명·발행일이 있을 때만 쓰고 없으면 [자료 필요].
2. 분모: 모든 비율에 계산 기준(분모)을 함께 적는다. 분모가 30 미만이면 "해석 주의".
3. 인과: 상관을 원인으로 단정하지 않는다. 원인 추정은 [확인 필요].
4. 구분: 사실·분석·제안을 구분한다. 가정은 [가정], 제안 문장 앞에는 (제안).
5. 문체: 개조식 업무보고(~함, ~임). 핵심 결론을 앞에 둔다. 이모지를 쓰지 않는다.
6. 검수: 결과물 끝에 수치 대조표(문장 | 수치 | 근거 위치 | 일치)를 붙인다.
7. 사람: 마지막 확인은 사람이 한다. 확인할 지점을 결과물에 명시한다.
8. 개인정보: 이름·연락처는 AI에 넣지 않는다. 식별자는 ID로 바꿔서 분석한다.

## 5. 자료 올리기와 개인정보 처리
- 받을 수 있는 파일: xlsx, xls, csv, txt, md. 여러 개를 올릴 수 있다.
- 엑셀은 브라우저에서 SheetJS로 읽어 시트별 CSV 텍스트로 바꾼다.
  - 불러오는 주소: https://cdnjs.cloudflare.com/ajax/libs/xlsx/0.18.5/xlsx.full.min.js
- 개인정보 열 자동 제거: 열 이름에 아래 단어가 들어 있으면 그 열을 AI에 보내기 전에 지운다.
  - 이름, 성명, 연락처, 전화, 휴대폰, 주민, 생년월일, 주소, 이메일, 보호자, name, phone, tel, mobile, email
  - 시트마다 열 이름을 따로 확인한다(시트마다 열 순서가 다르다).
  - 지운 열 이름을 화면에 알려 준다.
- 자료는 브라우저 안에서만 처리한다. 저장소나 서버에 올리지 않는다.

## 6. AI 실행 방식
- claude.ai 아티팩트의 `sample` 기능으로 페이지 안에서 Claude를 부른다. API 키를 넣지 않는다.
  - `const sample = await window.claude.use('sample')` — 쓸 수 없으면 null이 온다.
  - `await sample(지시문, { onText, signal, modelTier, cache:false })`
- 실행 단추를 눌렀을 때만 부른다. 반복문이나 타이머로 부르지 않는다.
- 대기 중에는 지난 시간을 초 단위로 보여 준다. 첫 글자가 나오기까지 1~2분이 걸릴 수 있다.
- 중지 단추를 둔다(AbortController).
- 실패 처리: 권한 없음, 요청 제한, 기타 오류를 구분해 안내한다. 자동으로 다시 시도하지 않는다.
- `sample`을 쓸 수 없는 화면에서는 실행 단추 대신 "지시문 복사"를 안내한다.

## 7. 결과를 파일로 받기
- 실행이 끝나면 결과 아래에 파일 받기 단추를 보여 준다.
- claude.ai 아티팩트의 `downloads` 기능으로 저장한다: `await downloads.save({ filename, data })`
  - 사용자가 저장 창에서 허용해야 저장된다. 거절하면 안내만 한다.
  - 허용되는 확장자에 hwpx가 없다. hwpx 파일들을 zip 하나로 묶어서 저장한다.
- hwpx 만들기
  - hwpx는 zip 형식이다. `mimetype` 파일을 맨 앞에, 압축하지 않고 넣는다.
  - 한 장 보고서 양식(hwpx)의 header.xml 등은 그대로 쓰고 `Contents/section0.xml`의 문단만 새로 쓴다.
  - 문단의 서식 번호(paraPrIDRef, styleIDRef, charPrIDRef)는 양식의 것을 그대로 쓴다.
  - 글자 겹침을 막기 위해 linesegarray는 비운다. 이모지와 제어 문자는 지운다.
- report 에이전트는 파일 3종을 만든다.
  - 한 장 보고서: 제목 / 개요 / 본문(실행계획·분석1~3·해결방안) / 결론+세부 2개 / 참고문헌
  - 3장 이내 보고서: 한 장 보고서와 같은 순서에 항목별 세부 내용 3~4개를 덧붙인다. 줄 수를 계산해 3쪽을 넘으면 세부 항목을 줄인다.
  - 분석 결과 전체: 수치 대조표를 포함한 원문
  - 두 보고서의 내용은 실행 결과를 `sample.json`으로 한 번 더 정리해 얻는다. 새 수치를 만들지 않도록 지시한다.
- 나머지 에이전트는 실행 결과 전체를 hwpx 1개로 만든다.

## 8. 아티팩트 화면의 제약 (지키지 않으면 동작하지 않는다)
- alert, confirm, prompt, window.print를 쓰지 않는다. 안내는 화면 안에 표시한다.
- `<a download>`로 직접 내려받기를 하지 않는다. 반드시 `downloads` 기능을 쓴다.
- 외부 서버로 fetch를 보내지 않는다. 외부 이미지를 불러오지 않는다.
- 스크립트는 cdnjs.cloudflare.com에서만 불러온다.
- localStorage는 없을 수 있다. try/catch로 감싸고, 없어도 화면이 동작하게 한다.
- 게시할 때 페이지가 쓰는 기능을 선언한다: sample, downloads.

## 9. 일하는 방식
- 한 번에 다 만들지 않는다. 단계마다 내가 화면을 확인한 뒤 다음으로 넘어간다.
- 각 단계가 끝나면 무엇을 만들었고 무엇을 확인해야 하는지 세 줄 이내로 알려 준다.
- 실제 개인정보가 든 파일은 만들거나 저장하지 않는다. 시험은 가상 데이터로 한다.
- 모르는 것은 추측해 채우지 말고 [확인 필요]로 표시해 물어본다.
